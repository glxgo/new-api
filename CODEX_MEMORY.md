### 2026-07-28 — Channel-cost design review replaces the standalone ledger with pre-consume record reuse

- Cost ratio remains an explicit channel property managed in channel add/edit/batch UI, not a group setting. Prefer nullable fixed-point `cost_ratio_ppm` (`1.0 = 1_000_000`) so missing and intentional zero remain distinct and arithmetic does not depend on float representation. Each selected attempt refreshes the context snapshot; only the final successful channel snapshot enters cost.
- The lower-overhead design reuses the existing unique `subscription_pre_consume_records` row rather than inserting a second durable row per request. Extend it with final sale quota, channel ID, ratio snapshot, high-precision cost numerator, and reserved/final/provisional/refunded state. In the same main-DB transaction, adjust the subscription amount and `user_subscriptions.cost_accumulator` by old-to-new deltas. Cleanup may remove only old final/refunded rows, never provisional ones.

Subscription revenue must snapshot actual order money/balance quota at activation; current creation copies plan entitlements but not paid revenue, while end settlement rereads mutable `plan.PriceAmount`.

### 2026-08-09 — Responses 顶层 error 字段与 Codex 终态兼容缺陷（只读诊断）

- `dto.ResponsesStreamResponse` 当前只声明 `Type/SequenceNumber/Response/Error/...`。OpenAI 官方 `ResponseErrorEvent` 和 CLIProxyAPI `v7.2.119` 的 `BuildOpenAIResponsesStreamErrorChunk` 都把 `code`、`message`、`param` 放在事件顶层；因此标准 `{"type":"error","code":"...","message":"..."}` 经当前 DTO 反序列化后丢失详情，`responsesTerminalError` 只能返回泛化的 `upstream Responses terminal event: error`。现有 `TestOaiResponsesStreamHandler_TopLevelErrorEventIsTerminal` 使用的是嵌套 `error`，没有覆盖官方顶层结构。
- `OaiResponsesStreamHandler` 虽会把 `type=error` 识别成失败、记录终态、退款并停止 handler，但 `sendResponsesStreamData` 会按原 `streamResponse.Type` 重建并下发 `event: error`。CLIProxyAPI issue #4854 已证明 Codex Desktop 不识别这种事件为正式终态，会报未收到 `response.completed` 并最多自动重试 5 次；官方提交 `3522e481` 对 Codex User-Agent/Originator 改发 `response.failed`，发布于 CPA `v7.2.125`，生产 CPA 仍是 `v7.2.119`。
- New API 自身在收到已输出数据后的终态错误时设置 `SkipRetry` 是正确的：服务器端重放会重复已经发给客户端的内容。安全修复应补齐顶层 `code/message/param` DTO 与官方形状回归，并对官方 Codex 客户端把需要暴露的确定性请求错误转换为协议有效的 `response.failed`；可恢复的提供方/传输错误应保留真实分类并由客户端重新发起，不能在已发首字节后盲目跨渠道重放。
- 本轮只完成源码和生产证据审查，没有修改、提交、推送或部署代码。运营侧 cyclone 样本、渠道分布和诊断查询造成的 MySQL 自动恢复事件记录在上级 `CODEX_MEMORY.md`。
