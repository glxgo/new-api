## 1. 已确认需求与方案默认值

用户已确认：由本站形成测试闭环，不依赖外部测试网站继续维护；按分组与模型展示；默认每三十分钟测试，后台支持调整间隔和时间；优先展示组内较好结果；答题正确、符合绘图要求为主要排序，美观为补充；请求可用性继续由现有模型状态展示。

新增明确需求：直接使用本站已有分组与渠道关系；关闭渠道、多组共享渠道、移组和增组时持续运行；提供类似参考网站的图形、分项时间线和详情；在现有设置体系中提供停止全部、隐藏全部、展示排序及完整管理能力。用户所说“分组至少保留一个”在本方案中按“至少保留一个渠道”理解；具体某模型仍须由该剩余渠道支持。

V3 新增明确需求：后台可仅取消某渠道的智商测试，不关闭业务渠道；渠道/分组改显示名称后仍对应原对象及其结果；所有测试 UI 基于飓星 API 当前 new-api 界面和组件优化，不另造一套风格。全站/分组内停测的作用域、固定分组身份与路由改名处理是本方案给出的具体实现建议。

V4 用户确认：名称统一“智商测试”；用户导航固定在“使用日志”和“模型状态”中间；点击上下移动必须交换整行；一键隐藏默认停止全部测试，也支持明确选择仅隐藏继续运行。优先级为调用与判分真实可验证、管理员可查实际数据、交互符合逻辑，再在现有 new-api 体系上完善整个测试功能的高品质 UI。这里的“全量优化”覆盖本次测试的全部页面与状态，不扩大为无关页面重设计。

V5 用户新增要求：图形作品在上、数据在下；用户文案专业且有利于理解本站价值；图片详情、完整测试方法说明和黑白主题均完善；后台能调控前台所有功能，自动读取并跟随新增分组/渠道/模型。三张不同图像与具体计划默认值按以下建议落实，不能为视觉丰富伪造独立样本或“满血”保证。

建议默认：每个执行目标每轮三次生成、一次视觉评审；三张展示位优先本轮独立渠道，缺位补近期真实作品，仍不足显示“作品更新中”；额外生成默认关闭；保留三十天。用户追加确认时间设置支持自定义：保留 15/30/60/120 分钟快捷选项，并加入自定义间隔、开始/结束时间和每周运行日；具体输入边界见 6.1。真实日预算及视觉评审模型在启用付费测试前配置。技术字段仍用 capability，不随文案变动迁移。

第一版覆盖能输出文本与 SVG 的对话/推理模型。SVG 是文本模型生成的图形代码，不等同于调用图片生成模型。Embedding、语音、视频、图片生成专用模型显示“不适用本套题”，不拿文本试卷给它们判零分；以后通过独立套题扩展。

## 2. 完整闭环与组件

```mermaid
flowchart LR
  A[本站分组、渠道、模型配置] --> S[分组订阅与变更同步]
  S --> B[按测试计划建轮次与合并等价任务]
  B --> C[本站执行器锁定渠道调用]
  C --> D[答案核验与隔离渲染]
  D --> E[固定视觉评审模型]
  D --> F[保存原始结果、评分、成本]
  E --> F
  F --> G[按当前归属分发并选择前三]
  G --> H[站内卡片、时间线、详情]
```

- Go 后端负责范围发现、出题、持久化队列、渠道调用、客观判分、排名和 API。
- 一个内部渲染服务负责把经过过滤的 SVG 转成 PNG，采用本地构建的固定版本 Chromium 容器。它无渠道凭据、无公网出口，不监听公网端口。
- 视觉评审调用运营者配置的固定多模态模型，输入题目和渲染 PNG，输出逐项判断与美观分。它是本站主动调用的一个模型服务，不依赖原测试网站；不会让被测渠道给自己打分。
- Default 与 Classic 提供相同的测试结果与管理能力，分别沿用各自组件库。
- 复用已有 SQL 数据库和 Redis，不增加独立测试网站、独立账号体系或另一套渠道配置。

## 3. 每轮实际测什么

每个目标每轮完成三项任务，各自独立请求，避免逻辑答题被长篇 SVG 挤占输出，或一道错误影响另一项任务。

| 请求 | 内容 | 生成上限默认值 | 判定方式 |
| --- | --- | --- | --- |
| A：逻辑与计算 | 一道保留的基准题、一道参数化随机题，一次返回两个答案 | 4096 输出 tokens | 本站求解器严格比较最终答案，逐题给 0/1 |
| B：规则图形 | 数量、颜色、位置、尺寸、遮挡关系组成的一张 SVG | 4096 输出 tokens | SVG 结构规则加 PNG 像素核验，五项各给 0/1 |
| C：场景绘图 | 鹈鹕等主体、交通工具、场景与指定细节组成的 SVG | 8192 输出 tokens | 六项语义要求逐条评审，美观另给 1–5 分 |
| 评审 C | 将题目和最终 PNG 交给固定视觉评审模型 | 1024 输出 tokens | 返回结构化评分、证据和不确定项 |

以上是最大允许量，不是实际消耗。包含隐藏推理 tokens 的模型按协议正确设置总输出限制，不能假设 `max_tokens` 对所有协议含义相同。执行前预检渠道参数覆盖后的真实限制；超过预算上限则阻止该次任务，不静默改动生产渠道配置。

### 3.1 逻辑题：程序生成题与答案

初始题库实现三类生成器，每类 4 个已审核模板；模板只换措辞和输入，不让被测模型提供标准答案。

1. 极值/保证问题：糖果题、抽取题。生成小整数参数，由枚举求解器得到标准答案；再用独立公式或另一种枚举策略交叉校验。
2. 约束排列：四至五个对象的先后或位置约束。枚举全部合法解，只有唯一解的题目才进入测试。
3. 状态演算：队列、集合、库存或栈的有限操作。由小型确定性解释器得到最终结果，用独立参考实现验证。

糖果题的例子：苹果圆形 7、桃子圆形 9、苹果星形 7、桃子星形 6、西瓜合计 12。不能得到目标配对时最大能取 `12 + max(7,6) + max(9,7) = 28`，保证得到配对需要 29。旧网站配置的 21 不沿用。

请求要求输出 `{"answers":[{"id":"anchor","value":29},{"id":"random","value":...}]}`。优先使用模型支持的结构化输出；不支持时允许剥离单层代码围栏再解析。只接受唯一的题号与最终值，不搜索全文是否出现标准答案，不接受“21 或 29”这种模糊答案。格式不符单列为格式问题，能力趋势中不当作明确答错。

每个 suite 版本有固定难度和参数范围，并从审核后的基准池选定一道锚题，在该版本内保持题目与参数不变。基准题用于同渠道纵向对照，随机题用于防止只记固定答案。每轮同一比较组使用完全相同的题目与顺序；模型自身采样输出不保证相同。更换锚题必须更新 suite 版本并重新积累基线。

服务端生成随机 seed，冻结题目、答案、模板版本和题目 SHA-256。题目生成先运行唯一性与答案校验，校验失败整道题作废并换 seed，不对模型记失败。对外只在结果发布后展示本轮题目及答案。

### 3.2 规则图形：可自动证明的绘图要求

示例题：在 600×400 白色画布上，左半区域画三个互不相交的红圆，右半区域画两个蓝色正方形；所有图形完整可见，并在底部写指定短标签。

五项客观检查为：数量、指定颜色、左右位置、非重叠且不裁切、指定文字。为让判定可复核，此类题明确限制使用 SVG 的基础形状和文字，禁止滤镜、任意路径模拟基本图形及隐藏/重复覆盖。

核验顺序：XML 正确性与允许标签 → 几何参数与变换 → 实际 PNG 中的颜色区域、数量和位置。文字同时检查可见 text 节点、位置、字号和透明度，图像级核验用于识别明显遮挡或空白；不声称仅凭 DOM 可以识别所有视觉语义。

初始实现四个任务族：数量与方位、嵌套与相交、柱状图数值比例、网格路径。每族至少四个模板；模板根据本地参考 SVG、故意错误 SVG 和像素容差完成校准后才启用。解析不支持的写法判“无法按本题规则评定”，而非凭猜测判正确。

### 3.3 场景绘图：任务完成情况与视觉呈现质量

两个维度可能相关，但不能直接相互推定，也不假设它们在统计上独立。数量、颜色和位置全部符合题目，仍可能构图粗糙；画面精致也可能缺少指定物体。如果题目明确要求清晰、对齐或特定布局，则这些本身属于任务要求，不能遗漏后仅作为审美扣分。评价表逐项对应题意，避免重复计分；视觉评价说明其判断依据与局限。

用户要求取消首页的口号式评分表述，不等于已要求取消既有评分维度或更改优选顺序。当前仍沿用已确认的任务完成情况优先、其他成绩相同时参考视觉评价的规则；前台使用完整专业说明，不把两者描述成对立关系，也不宣称“正确即必然美观”。真实相关程度待校准样本验证，不据此制造综合智力分。

随机组合由审核过的题库生成。例如“鹈鹕骑自行车经过海边，戴红围巾，车篮内恰有两个橙子，太阳位于画面右上方”。每轮固定六个清晰可见、可逐项评审的要求，避免互相矛盾或无法从静态图验证的动作。

首批材料：6 个主体 × 8 个交通工具 × 8 个场景，加颜色、数量、方位约束。只从合理组合白名单抽取，不声称所有笛卡尔积组合难度相同。第一版使用静态 SVG，动画题另设套题，不影响现有静态比较。

视觉评审读取 PNG，不读取 SVG 注释、模型自述或答案字段，返回：六项 `pass/fail/uncertain`、每项可见证据、画面完整性、审美 1–5、总体置信度。题目与评分指令来自本站，图片及其中的文字均视为待评内容，不作为评审指令。

审美 rubric 固定为构图 0–2、主体辨识与细节 0–2、色彩协调 0–1，界面可显示 1–5 等级，但不把风格偏好包装成客观智力。

上线校准集至少 60 张：明确正确、缺少要求、仅写文字冒充物体、漂亮但任务错误、空白/截断、含干扰指令各至少 10 张，由人工定标签。要求明确错误样本无误判通过、客观项与人工一致率至少 90%；未达到则相关模板不启用。评审模型、提示词、rubric 和图像尺寸都固定版本。

评审不确定或响应缺失时标记“待评”，不默认通过。每轮抽取约 5% 样本重复评审以观测一致性，分歧记录并排除该项自动排名，不能不断重复取最好评分。公开作品先完成过滤与渲染；无法安全渲染的原始内容只在受限管理视图作为转义文本查看。

## 4. 渠道如何接入：沿用本站配置

### 已查明的代码边界

分析基线为此前已核对的 GitHub `main` 提交 `247b243014f3418fe84b398afc1a2299cab8620f`，V6 源码检查使用该提交的只读参考树。当前编辑用工作树仍为旧基线，后续开发前须重新核对 main，并以经核对的最新提交建立干净分支，迁移本方案文档，不能从旧基线构建上线。

`controller/channel-test.go` 已通过 `SetupContextForSelectedChannel`、`GenRelayInfo`、`ModelMappedHelper` 和 adaptor 完成指定渠道调用及参数覆盖；现有请求内容主要是固定 hi，返回值也不包含完整作品。因此需要抽出可复用执行器，不能简单调用旧“测试渠道”接口并假设能获得 SVG。

`IsChannelTest` 还会影响客户端请求头透传；旧测试使用测试用户分组上下文。必须显式传入目标分组、模型、协议与测试档位，并预检请求覆盖后的实际参数。不能声称现有探测已经与用户完整请求链完全一致。

本轮进一步核对 `controller/channel-test.go`：`readTestResponseBody` 对流式日志只读前 8 KiB，`validateStreamTestResponseBody` 看到一个非空 SSE data 事件即可通过；`coerceTestUsage` 在流式 usage 缺失时构造估算输入用量；测试超时从 `context.Background()` 创建，`recordConsumeLog=true` 会写“模型测试”消费日志。以上行为服务原可用性测试，不能直接当作完整作品捕获、完成性判断、实测成本或可取消的智商测试实现。具体替换与证据门槛见第 18 节。

### 推荐实现

- 定义内部 `CapabilityProbeExecutor.Execute(ctx, spec)`，输入完整 dto 请求、固定 channel ID、分组、原始模型、协议、生成参数、任务 ID 和超时；输出标准化回答、原始协议文本、usage、实际上游模型、配置指纹与诊断。
- 最小化重构 `controller/channel-test.go`，由 controller 层提供 executor 实现，在 main 中注入调度服务；避免 service 导入 controller/middleware 造成现有依赖环。原人工测试与可用性探测保持原来的默认请求及返回行为。
- 使用本站 adaptor、模型映射、参数与静态头覆盖，明确禁用自动跨渠道重试；人工错误答案不会触发渠道禁用、调权、切流或现有探测状态更新。
- 对要求特定客户端头/协议的渠道定义独立测试 profile，使用管理员批准的非敏感固定测试头；无法复现必要上下文的渠道标记配置待补齐。不能把缺少客户端头得到的错误归因于能力，也不借用普通用户的 Cookie 或会话。
- 不向浏览器提供上游 Key，不为此创建持有 root 权限的公开测试令牌。
- 探测属于运营合成请求：单独保存上游用量和预算账本，不扣普通用户余额、不写其消费日志、不计入真实用户健康与负载统计；对全部适配器的计数/扣费/日志钩子做专项验证，不能只靠 `recordConsumeLog=false` 推断无副作用。
- 遵守生产渠道限流，探测优先级低于用户流量。共享并发额度中的临时占用是实际资源消耗，不能以“不计业务统计”为由绕过渠道限制。

### 目标与分组对应

从启用的 abilities 中获取真实 `group + model + channel` 关系，结合渠道启用状态及人工配置的测试范围形成目标。不能因为渠道同属一个组，就假设它支持组里每个模型。

关系是多对多：分组决定结果展示归属，渠道决定实际执行对象。业务现有关系为唯一来源，测试系统只保存派生订阅及历史快照，不要求运营者再维护一套“分组对应渠道”表。

拆成两种身份：`group_subscription = group_uid + requested_model + profile`；`execution_target = channel_id + requested_model + protocol + effective_profile + execution_revision`。group_uid 是拟新增的智商测试分组固定身份，发送时解析为已核实的当前业务路由名称，详见 13.6。一个执行目标可被多个分组订阅。相同半小时槽、suite、题目 SHA-256、有效请求签名相同的任务只执行一次，再分发到合法订阅；纯展示名称和组内售价不同本身不导致重复测试。

有效请求签名在本站完成模型映射、参数和请求头覆盖后生成，包含 endpoint、实际模型、协议、system/user 内容、推理与输出限制、凭据版本、代理/客户端档位、会影响请求的分组上下文。敏感字段使用服务端 HMAC/版本号，不把凭据写入签名明文或日志；仅允许剔除已证明无语义影响的 trace ID 等字段。动态表达式、客户端头或上下文无法证明等价时必须拆开执行。不同 channel ID 即使地址相同也不合并。

例：C1 同属 A/B，两组调用条件相同，则本轮 C1 的三项生成及评审各执行一次，A/B 各自展示该结果并在各自组内排序。如果 A 为 medium、B 为 high，则形成两个目标，界面明确档位。全站成本只记一次；分组详情显示“共享样本”，不能把共享记录累计为多个独立样本。

多 Key 渠道每个目标每轮按既有策略选一个可用 Key，同轮三项任务固定这个 slot；执行器只在内存使用凭据，持久化记录保留内部匿名 slot，不记录密钥。中途 slot 不可用则本轮未完成，不悄悄换 Key 拼成一份试卷。该结果只代表该次抽样，不代表池中每个账号；不同 key slot 不可冒充三个不同渠道。

测试清单对本站现有及新增分组、渠道、模型全部自动发现，无需人工同步或另建映射。已启用组默认 follow_group_membership=true；推荐首次启用时配置“新分组自动继承测试策略”：符合批准模型范围/协议/价格/预算的新增组及成员自动接续，未知模型自动列出适配原因但不擅自扩展付费范围。自动纳入不自动公开私有组。人工排除始终有效；详细清单、策略继承和适配验证见 14.9。

拓扑变更成功后发布轻量事件，同时每 60 秒从数据库对账；每次发送前重新校验状态/关系/配置，最终排名发布时再校验。事件提高时效，对账防丢失，发送前校验是最后约束。详细关闭/移组/补测规则见第 13 节。

### 4.1 每个分组、渠道与模型的真实调用证明（V6）

“全部测到”以清单及证据判断，不能以页面出现三张作品判断。发现清单包含全部已知对象；应测清单为有效分组—模型—渠道关系与已批准范围的交集。每轮应测清单中的每个独立执行目标都安排任务，展示前三不缩减执行范围。停测、禁用、模型不支持、预算不足等对象仍在管理清单中显示原因，不从清单删除以制造覆盖完成。

执行按以下顺序建立确定性约束：

1. 从 channels、abilities、分组权限和测试策略解析 `group_uid / routing_key / channel_id / requested_model / profile`，保存关系版本；abilities.Enabled 与实际渠道状态都要检查，不能只依赖左连接的启用 ability 查询。
2. 明确区分运行测试的内部执行身份与被测目标分组。旧代码从测试用户取得 `group`，不等于所选分组；新执行器必须正确设置目标 `UsingGroup` 及所有依赖分组的覆盖上下文，逐项证明与对应业务路径的有效请求一致。执行身份只用于授权和审计，不借用其分组替代目标。
3. 显式锁定 channel_id，通过本站对应 adaptor 发出；不经过随机选渠道逻辑，不失败后换另一个渠道冒充本目标成功。映射前后模型、协议、代理、参数/头覆盖和版本均可追溯。
4. `SetupContextForSelectedChannel` 每次都会调用 `GetNextEnabledKey()`；因此不能原样调用三次后宣称同轮锁定 Key。应抽出内部“选取凭据”和“装配渠道上下文”步骤，在一个目标的整套题内固定同一 slot/凭据版本。该能力不暴露为普通用户可传入的选渠道请求头。失效则记录本轮未完成，下一轮按策略重新选择。
5. 发送许可前再次验证关系、停止策略、配置版本和预算；在途配置变更尽力取消，并保存已发送事实，禁止把旧版本结果发布成新配置证明。跨组复用必须先分别解析有效请求，确认完全等价及合法订阅，不能仅因 channel_id 相同就跳过其他组的上下文验证。
6. attempt 在网络发送边界记录所选渠道/匿名凭据槽、脱敏目标地址、有效请求指纹、时间和可用的上游 request ID；完整回答、用量来源、作品哈希及判分再关联到同一 run。配置回显只证明准备调用；完整网络响应才证明该次请求收到回答，二者不能混用。

管理员“范围与适配”展示覆盖矩阵：分组 → 模型/档位 → 渠道；每行能跳到最近的实际 run。列出应测、已获得完整回答、已完成判分、待执行、失败、受限/排除，并分别呈现物理调用数和分组归属数。覆盖只对明确的周期及 execution_revision 有效；变更 endpoint、映射、关键参数或凭据版本后旧样本保留历史，新配置恢复为待验证。答错仍是一次有效完成的测试，判分服务故障不能归因于被测模型。

该证明确认本站请求走到配置的上游及收到的响应，不能仅凭上游自报的模型名称认证其内部真正调用了哪个厂商/权重。多 Key 渠道仍是每轮抽一个 slot，不等于逐个账号全覆盖。全目标真实验收见 18.4。

## 5. 三个结果如何选、如何补位

2026-09-22 用户明确的展示循环：新一轮执行期间，继续展示上一轮的完整题目、图片和评分；本轮全部任务结束后，按“分组＋模型”一次性发布新快照，旧快照进入历史。禁止逐个渠道先到先换，禁止新题配旧图，禁止在等待期间清空。新一轮没有可展示作品时保留上一轮及真实时间；首轮尚无历史时才显示等待状态。下文单项独立计分指结果含义与故障隔离，不代表在轮次执行中逐项替换前台快照。

每个分组按模型及测试档位分别展示，不能把 gpt、Claude、不同 reasoning effort 或不同题目版本混成一个排名。

每轮先得到渠道成绩元组：

`(逻辑答对数 0–2, 规则图形通过数 0–5, 场景要求满足数 0–6, 审美分 1–5)`

按元组从左到右降序比较。也就是先比答题，再比规则图形，再比场景要求，最后比美观；不使用加权总分让漂亮图片抵消答错。全部相同再以稳定匿名渠道编号排序，速度不作为能力排名因素。界面分别显示四项，不发布伪精确的“智商 97 分”。

- 每个渠道本轮只保留一次有效试卷成绩参与排名。不能通过重新生成作品挑最好一次。
- 完整四项成绩用于本轮综合优选，不能把未知分数当零或通过。为保证单个题型故障不拖住整个页面，各题型结果独立发布；场景待评时仍发布逻辑与规则图形时间线，图片可在安全渲染后标“待评”展示。页面明确区分“综合优选”“单项结果”“上一轮”，不将不同轮次或完整度混成一个排行榜。
- 超过三个渠道：显示前三，用户可展开该组其他已发布样例；管理员可查看所有原始记录与未完成原因。文案为“本轮优选”，不把优选三条宣传成全组整体通过率。
- 恰好三个：直接显示三条真实结果。
- 两个：前两格为本轮 A/B 的真实作品；第三格优先按 5.1 补一张近期真实作品，标“近期作品”及实际时间，不包装成第三个本轮渠道。
- 一个：本轮作品一张，另两格补该组合法的近期独立作品；没有足够历史时用“作品更新中”占位，不默认重复同一图。
- 零个：只有实际仍在执行时显示“本轮结果更新中”；已结束且无有效结果显示“本轮未形成有效结果”，人工停止显示“测试计划已暂停”，并保留最近已发布时间。仅在存在合法历史时呈现明确的“近期作品”区，没有结果就保持空状态。
- 本轮尚未发布：可保留上一轮快照并明确时间及“本轮更新中”；不能在旧作品上显示本轮时间。上一轮渠道已经关闭、停测或移出时不再进入当前作品候选，只在历史视图保留。过期阈值默认两个应执行周期，运行时段之外显示下一计划时间，不能误报迟到。

用户点击图形页签时可选择“规则图形”或“场景作品”，默认场景作品；逻辑答案以独立详情显示。综合优选的三个渠道依据完整成绩选择；进入单项视图时允许按该题型得分选前三，必须显示“单项优选”，不暗中改变综合优选含义。场景主观评审整体不可用时按已知客观条件展示“待评作品”，不生成审美排名。

### 5.1 三张不同作品的真实来源与费用

三张作品与三个渠道是不同概念。推荐缺位策略 gallery_fill=recent：先保留本轮前三的独立渠道作品，再从当前有效成员、同组合法历史、同模型/profile/执行版本与同题型中取最近不同作品补位。历史仅取最近 24 小时内且未超过两个应执行周期的记录，按时间从新到旧，不从三十天历史挑高分冒充近期表现；规则/题库版本不同只在历史页分段展示。加入新组前的记录不会当作该组既往成绩，仍按 13.3 的参考规则单列。

补位按 artifact/run 去重，并检查规范化 SVG 或解码 PNG 的内容哈希；若模型两次返回同一张图，不宣称不同作品，不通过换底色、裁切、重画或镜像包装新生成。每张卡保存 display_source、source_run_id、question_id、真实时间和来源匿名代号；点击看到这张图自己的题目与评分。历史补位只充实画廊，不加入本轮排名、完成率或样本数，不在历史图片上挂当前轮次成绩。

示例：组内只有 C1，本轮 14:00 与历史 13:30、13:00 各有真实不同作品，则三格显示“本轮精选 14:00 / 近期作品 13:30 / 近期作品 13:00”，来源都可查看为同一匿名渠道。只有本轮一张时显示一张作品及两个“作品更新中”，不承诺数据不足仍有三张真实新图。

后台另提供 gallery_fill=repeat（兼容需求）与 current_only（只看本轮）。选择 repeat 时用户标签改为“同一作品”，辅助文案为“来源：样本 C4 · 测试于 14:00”，详情说明“与作品 1 引用同一测试结果”；不能只换成“独立样本”或“多源验证”。默认 recent，重复不会扩大统计。

确需首轮同一渠道就提供多张新图，可配置每目标的场景样本数 K=1/2/3，默认为 1。额外样本必须真实单独生成与评审，每个 sample_index 在派发前冻结题目/seed，run 唯一键增加 sample_index/purpose；所有目标按同一配置执行，不能答错后反复生成挑最好。sample_index=0 是主测并用于完整试卷排名；额外样本标“补充作品”，仅进入作品集及单独补充样本统计，不能替换主测或提高本轮综合分。共享组引用同一补充 run；单独停用某组不重复生成。

完整轮次请求数变为 N×(2+K) 次生成、N×K 次基础评审；增加 K 要显示新增日费用、容量预检与生效轮次，并受总预算控制。先保障全部目标主测，补充作品只用剩余额度。即便实际生成 K 次也不能保证图像必然不同；重复保留真实记录，画廊去重后补历史或占位，不循环花钱直到不同。

## 6. 调度、重试、崩溃与蓝绿并存

- 按持久化测试计划创建轮次，默认整点/半点；调度唯一身份是 schedule_revision + scheduled_at_utc。加有界抖动分散请求，不按上次完成时间累积漂移；时间设置见 6.1。
- 默认全站同时 4 个被测生成请求，同渠道 1 个，渲染 1 个，视觉评审 2 个；单次上游超时 180 秒，渲染 10 秒。预检要求范围与主测能在当前周期的派发窗口内完成，不以缩短周期绕过容量限制。
- 周期长度为 T：新生成截止为轮次起点 + 2T/3，封存截止为 +5T/6，下一轮按计划启动；默认 T=30 分钟对应 20/25 分钟。截止后新请求取消，已发请求最多执行到自身 deadline 与封存点中的较早者；未完成如实记录，不无限追赶。
- 仅能证明请求尚未发送，或上游明确拒绝且未执行生成，或有已验证的幂等能力时允许一次退避重试，遵守 Retry-After 并记录两次尝试。429/502/503/504 本身不保证未生成/未计费；接收状态不明、断流、已收到内容、答错、格式错、截断均不自动重新生成。视觉评审针对同一已存 PNG 恢复，不再调用被测模型，其重试同样记录费用。
- master 节点且功能启用才竞争 Redis 租约；每 20 秒续租，租约 90 秒。slave 候选不争抢。任务表以轮次、目标、题目建立唯一键，领取使用数据库条件更新与 owner fencing token，不能只用进程锁。
- 租约丢失时停止领取并取消本机未完成请求，旧 owner 不能提交排名。发送前先持久化 dispatch 标记；崩溃后已标发送但无结果的任务设为 outcome_unknown，不自动补发，避免可能已经计费的请求再次付费。
- 数据库唯一键和 lease 不能保证外部 API 的 exactly-once：计划明确接受极少数未知结果缺失，优先避免重复付费。只有上游支持并验证幂等键时才按该能力恢复。
- Redis 或数据库异常时暂停调度，保留最近展示结果；不降级成多个进程各自调度。
- 调度采用“覆盖优先、组间轮转、组内最久未测优先”。先让每个启用的 group/model/profile 得到至少一个完整目标的执行机会，再测该组其余渠道；共享目标可同时满足多个组的机会。不会总从最好渠道开始，也不因某组处于页面第一位就耗尽全部预算。
- 逻辑生成、图形生成、渲染、视觉评审使用独立有限队列与超时；失败隔离到具体任务。视觉评审积压只影响其评分，逻辑题和后续轮次继续；持久化已生成作品以供恢复，积压达到容量上限仅暂停相关场景生成，不能无限堆积。
- 每组基础覆盖所需的整个目标任务费用在派发前预留；其余渠道增量执行。预算不足以覆盖所有组时明确标“覆盖不足”并提示管理员，不承诺突破费用上限仍全量运行。余额/服务恢复后健康检查自动接续当前有效槽或下一槽，人工停止除外。

### 6.1 后台可以调整间隔、开始时间与运行时段

“测试设置 → 测试计划”提供：15/30/60/120 分钟快捷选项（默认 30）与“自定义”数字输入、IANA 时区（默认 Asia/Shanghai）、首次计划日期和对齐时刻、每周运行日、全天/自定义每天开始与结束时间（可跨午夜）、生效时间。自定义间隔首版建议支持 1–1440 整数分钟，例如 20、45、90 分钟；不得静默取整为预设值。UI 与 API 校验空值、0、负数、小数、超界、空运行日、无效时区和零长度窗口；全天用明确选项，不用相等的开始/结束时间猜测。支持输入不等于任何范围都能以该频率执行：容量检查须覆盖当前全部主测、渲染和评审时长，低于安全执行窗口时返回具体原因与建议最小间隔，不静默缩题、删目标或增加并发。

保存前展示未来五次执行时刻（含日期与 UTC 偏移）、今日剩余次数与预计费用；自定义 37 分钟等不整除一天的间隔同样沿 UTC 锚点连续计算，不在每天午夜重置相位。页面数据刷新另设 30/60 秒或手动，刷新不发模型请求。第一版统一全站计划，各组继承，避免同模型跨组随意错开而破坏公平比较及共享去重；不要求管理员编写 cron。

调度按 UTC 锚点计算 anchor_utc+n×T，再按所选时区的运行窗口过滤，存每次具体 UTC 执行时间。支持夏令时的时区显示 UTC 偏移：不存在的本地开始时间拒绝保存，重复本地时间须明确偏移；跳过窗口之外的轮次，不将未安排时段记失败。跨午夜归属于窗口开始日；周日到周一等情况写入验收。

修改使用 expected_schedule_revision，先 dry-run 容量/费用/时区校验再持久化；默认从当前轮次封存后的未来时刻生效。旧轮次保存旧配置快照，新计划从未来第一个合法时刻开始；不把过去时间补发，不在切换点创建双轮次，不重置预算、停止或排除状态。两种计划的图表按真实时刻分段，不能仍画固定 48 格并填造不存在的轮次。全局 stop 时可以保存计划，但不会因此启动。

抖动不得超过 min(60 秒,T/30)，每次派发还需剩余时限能容纳其有效 deadline；15 分钟周期不允许套用 20 分钟旧截止。补测上限从“每半小时一次”改为“每 schedule round 一次”，修改计划不会清空跨切换的渠道补测冷却，至少保留原周期冷却到期以防刷请求。价格未知、配置容量不足或预估超预算时显示问题并拒绝直接启用该计划，当前有效计划可继续。

预算公式用计划实际次数 R：全天固定 T=30 分钟通常 R=48；带运行日/时段/夏令时以计划预览计算。基础每天生成约 R×N×(2+K)，评审 R×N×K，加有上限抽检/重试/补测；N 随拓扑变化，预留账本仍是最后约束。新周期生效后方法说明、倒计时、过期阈值、覆盖数与预算预估同时更新。

覆盖记录分别保留“轮次开始时计划数、现行有效成员数、已完成独立样本数、因改组/关闭撤销数”；不得关闭一个失败渠道就改写本轮历史分母。当前卡片显示现行覆盖，历史格显示当时计划与实际完成，并明确变更原因。

用户读取接口（登录可见，沿用站内公开分组名单，服务端过滤）：

- `GET /api/capability/groups?model=&profile=`：卡片、已发布轮次、三个样例与更新时间。
- `GET /api/capability/groups/:group_uid/history?model=&profile=&range=24h`：轮次时间线；支持 24h/3d/7d，分页限制，不用显示名称作为主键。
- `GET /api/capability/runs/:public_id`：脱敏题目、回答、评分证据、时间与作品引用。
- `GET /api/capability/artifacts/:public_id`：经校验的 PNG 或隔离 SVG，校验对应可见分组；不公开上游 URL、渠道真实名称或凭据。

管理接口统一 RootAuth，读取诊断可另授现有管理员权限：

- `GET /api/capability/admin/targets`：发现目标、未覆盖/不适用原因、预算预估。
- `PUT /api/capability/admin/config`：范围、限额、题库、评审模型、自动开关。
- `POST /api/capability/admin/preview`：只生成题目与费用估算，不调用上游。
- `POST /api/capability/admin/runs`：经权限和预算校验的手动测试，带请求幂等键；独立标记为 manual，不能替换计划轮次以刷高分。
- `POST /api/capability/admin/stop`：一键停止全部，持久化停机状态、取消排队/重试/补测/评审，尽力中止在途。返回控制版本及 stopping/stopped 状态；已发生费用不回退。
- `POST /api/capability/admin/resume`：预检后恢复，安全重排当前未发送任务，错过时段不重放。
- `POST /api/capability/admin/display-action`：显式 action 为 hide_and_stop / hide_only / show_only，带 expected_control_revision；hide_and_stop 原子修改运行与可见状态，前端“隐藏测试”默认发送该 action。缺少 action 拒绝，不通过隐含参数猜测行为。
- `PUT /api/capability/admin/layout`：原子提交题型/分组/模型的展示顺序，带 expected_layout_revision，冲突返回 409。
- `GET /api/capability/admin/runtime`：控制状态、worker 心跳、对账、队列、覆盖、费用和故障；用户隐藏时管理员仍可进入。
- `PUT /api/capability/admin/channels/:channel_id/testing-policy`：明确 scope（all_groups/group）、group_uid、可选模型/profile 与 excluded；带 expected_control_revision，仅更新能力停测策略。
- `PUT /api/capability/admin/groups/:group_uid/presentation`：保存该组的显示别名、描述模式/覆盖及 expected_presentation_revision 到展示草稿；由统一 presentation/publish 应用，不修改业务路由键或倍率。返回继承来源、有效预览值和版本。
- `GET /api/capability/admin/runs`：分页运行记录，按时间、组 UID、渠道 ID、模型、题型、真实/模拟来源、完成状态及判分状态筛选。
- `GET /api/capability/admin/runs/:run_id`：计划、派发、各次 attempt、脱敏实际参数与回答、判分依据、制品哈希、成本来源和发布去向；管理权限独立于用户展示开关。
- `POST /api/capability/admin/schedule/preview`、`PUT /api/capability/admin/schedule`：只读预估与带 revision 的计划保存，返回生效时刻/未来五次计划，不隐式开测。
- `GET /api/capability/admin/discovery`：当前全量发现清单、合法关系、适配状态、继承策略、同步时间/延迟；`POST .../discovery/reconcile` 仅触发受限只读源对账，不调用模型。
- `PUT /api/capability/admin/presentation`：保存后台展示草稿；`POST .../presentation/publish` 发布经过校验的原子版本；`POST .../presentation/restore` 还原某版展示配置，不更改运行与评分数据。

所有读取 DTO 返回相应 `control_revision / presentation_revision / topology_revision / metadata_revision / observed_at`；用户组 DTO 包含 group_uid、授权可见的当前业务名称、有效显示名称/描述、配置倍率值及状态、继承来源，绝不包含渠道凭据。metadata_revision 为拟新增的源配置版本或一致快照指纹，并非声称现有分组接口已经提供版本。管理 runtime 返回各活跃 worker 已应用的控制版本和未确认原因；公开查询支持 `min_revision` 的一致读语义，版本不足时读取权威快照或明确返回稍后重试，不能用旧数据冒充保存后的状态。接口名均为拟实现契约。

策略更新返回本次解除/新增的限制、仍生效的其他限制、受影响订阅数及在途数。批量操作同样传固定 ID 和明确 scope；接口拒绝缺少作用域或引用已删除身份，不通过名称查找猜测目标。正式路由改名走现有业务改名流程及 13.6 的承接钩子，不提供绕开业务检查的测试侧改名后门。

配置读取和写入以 capability_control 及其关联配置为唯一来源，设置页通过专用服务读取，不同时在通用 option 表保留第二份控制状态。普通保存接口不能隐式覆盖停止状态，恢复必须调用显式 resume。手动执行也服从全局停止、渠道/分组停测、预算和范围约束。

公开接口不包含任何执行能力。未公开组的 run ID 即使被猜中也不可读取。原始响应可能含上游错误中的秘密，管理员详情也需脱敏，不能直接透传错误正文。

## 8. 页面与能力波动提示

用户导航顺序固定为“使用日志 → 智商测试 → 模型状态”。Default 新路由建议 `/intelligence-test`；名称进入 i18n，技术 API/表名继续沿用 capability，不因显示名改变反复迁移。名称不意味着可推断人类 IQ 或仅凭测试证明上游实际模型身份；页内方法说明展示各题型真实结果。

已核对 Default 的 `hooks/use-sidebar-data.ts` 中 Usage Logs 后紧接 Model Status，插入位置明确；`hooks/use-sidebar-config.ts` 当前把两者映射到 console.log。新功能增加独立 console.intelligence_test 可见项，并与服务端 visibility 取交集，不复用 log 开关导致隐藏测试时连日志/模型状态一起消失。新路由用正式路由生成器更新，不手改生成树；默认名单、管理员模块配置及用户偏好都需要兼容新项。Classic 的已检查 SiderBar 使用日志后是绘图日志，不能假称它现成有相同模型状态入口；第一版在其使用日志后添加智商测试，若该主题提供模型状态入口，则保持三者相邻顺序，不额外建设另一个模型状态系统。

管理入口固定为“系统设置 → 运维 → 智商测试”，位于“监控与警报”之后。展示页与管理页分开；隐藏展示页不会使管理员找不到控制入口。页面布局与操作详见第 14、15 节。

顶部：分组/模型选择、档位、24h/3d/7d、最近完成时间、下轮预计时间、简明测试方法。页面打开时轮询只读接口，每 30 秒刷新；不会触发测试。

分组卡片：组名/模型 → 三张作品与来源/时间 → 四项成绩和分项历史。作品始终先于数据；不重复放请求成功率/可用性柱。点击进入大图、题目、答案和判定证据；渠道对外使用组内稳定匿名代号。

时间线固定对应真实测试轮次，颜色分别表示任务达标、未达标、待评/无结果。所有样本分布可查看，卡片优选不影响历史事实。复制补位只影响布局。

“能力波动”只在固定基准题、同 channel/model/profile/suite 的历史内判断：至少 54 个有效锚题样本，参考较早 48 个样本的正确率；仅当参考正确率至少 90%、最近 6 个至少 3 次明确答错时提示“近期基准题表现下降，建议复核”。最近 6 个与参考窗口不重叠。此为可解释的运营提示阈值，不是统计证明；初期可展示题目通过情况而不展示降智结论。

随机题与主观审美不参与该告警阈值；格式错误、传输错误、评审不确定与无数据也不算明确答错。渠道配置、suite、协议或推理档位变化即开启新比较序列。评审版本变化的场景分数单独分段。分组优选成绩和某个渠道纵向能力趋势分别展示，不能因为本轮换了入选渠道就声称模型退步。

## 9. 渲染隔离与结果保留

- XML 解析器禁用 DTD/外部实体，采用标签、属性、URL 协议白名单；去除脚本、事件、foreignObject、外部字体/图片/CSS、链接与动画。保留原始响应但不执行。
- 单份 SVG 最大 200 KiB、原始可见回答最大 400 KiB、固定 1024×768 渲染画布；超过限制标记截断/无法评定，不能补闭合标签后直接判通过。
- 渲染容器非 root、只读根文件系统、tmpfs 工作目录、无宿主或业务数据挂载、无 Docker socket、无外网。限制 1 vCPU、512 MiB 起步并经本地样本压测调整，超时杀死本次浏览器子进程。
- 渲染采用内存 SVG、内嵌样式和固定字体；服务只接收后端上传的字节，不接受任意 URL。对图片使用静态 PNG 作为默认展示，SVG 下载/详情使用隔离域或 sandbox+CSP。
- 保留 30 天记录与作品、180 天不含原文的统计；默认制品卷软上限 10 GiB，清理过期记录，接近上限暂停新的作品任务并提示管理员，不静默丢失仍在保留期的结果。
- 存储估算：每天约 R×N×[(1+K)份SVG及PNG+(2+K)份可见回答]；默认 R=48、K=1。N 为跨组等价目标数，近期补位不复制制品。按实际样本测容量，不承诺固定存储费。

## 10. 费用与容量开关

设 N 为本轮按有效请求条件跨组合并后的独立执行目标数，R 为当日计划轮次，K 为每目标场景样本数。完整方案每日生成请求数 R×N×(2+K)，基础视觉评审 R×N×K，再加约 5% 评审抽检、有限传输重试及有上限的配置变更补测。默认 R=48、K=1；多个组引用一份样本不增加 N，近期作品补位不额外调用模型。

例如 N=10：每天 1440 次被测生成、480 次基础评审，另约 24 次抽检；不是每个分组三次，也不是只有三张展示图就只测三条渠道。

金额按实际渠道输入/输出/缓存/推理计价及评审模型计价计算。使用明确币种和价格版本，站内销售倍率不能直接当作真实上游成本。未知实际价格的目标显示“成本未知”，补齐成本价或运营者认可的保守上界后才自动启用。

执行前在预算账本原子预留本次最大费用，成功后按 usage 结算并释放余量；重试和评审也预留。已发送但 usage 未知时保留保守预留并标待核对，不能视为零消费。测试账户、渠道总并发与预算均由后端强制执行。

上线默认 `run_state=stopped`、`visibility=hidden`、日预算未配置视为 0，不产生付费请求。日预算、范围及视觉评审模型是启用配置；确定这些之前可以完成所有代码、模拟验收与页面，不阻塞开发。

启用前先估算全轮容量。若全量超过预算或二十分钟工作窗口，管理员选择缩小模型范围、提高已确认预算或调整并发，不能悄悄改成轮询少数渠道却仍标全量测试。

1. 每类逻辑生成器至少 1000 个固定 seed，由独立求解器交叉验证；歧义题不会入库执行，29 被正确判定，出现“21/29”不误过。
2. 规则图形夹具涵盖正确、数量错、颜色错、位置错、遮挡、不可见文字、截断等；代码中声称正确而 PNG 错误不能通过。
3. 场景校准集达到第 3 节标准，评审失败不会默认高分；漂亮但答错的结果排在逻辑正确者之后。
4. 两套前端验证 0/1/2/3/5 渠道、近期补位/补充作品/同一作品、过期、待评、手机、明暗主题、历史分页与无权限组；画廊不污染本轮统计。
5. 用模拟 HTTP 上游验证 Chat/Responses/Anthropic/Gemini 接口、模型别名、参数覆盖、流断开、截断、请求头配置、usage 缺失；不依赖仅检查模型名猜协议。
6. 构造两 master 与一 slave、lease 失效、数据库不可用、发送后崩溃，验证只有合法 owner 发布结果，未知发送不自动重发。
7. 三数据库验证迁移、预算并发预留、任务唯一键、事务领取与清理；预算不足时在网络请求前停止。
8. 普通用户钱包/订阅/分润/消费日志与真实请求统计不受测试影响；上游测试费用全部进入独立账本，渠道限流仍有效。
9. 恶意 SVG 不执行脚本、不访问网络或本地文件；渲染超时不拖垮业务进程；普通用户不能触发测试、读取隐藏组或上游秘密。
10. 模拟时钟完成两个相邻半小时槽并验证错过轮次不补测；获费用授权后选少量真实目标做受控验收，再观察至少两个实际周期。

发布只增加表/字段，保留旧版可运行能力；迁移先在本地三数据库验证，在生产经授权单独执行，不让 3010 slave 候选自动迁移。

沿用既有蓝绿：本地构建两前端/Go/渲染镜像 → 校验与备份 → 候选 3010（slave、调度关闭）→ 验收 → Nginx 切候选 → 旧 3000 连接与指标排空 → 重建 3000 → 验收并切回 → 3010 排空。首次发布全程能力调度关闭；确认真实测试范围、预算与 judge 后再启用。后续发布停领新任务并排空探针，冻结题库与轮次版本，保留现有业务排空流程。

回滚先暂停能力调度、停止渲染接收新任务，再切回旧制品；新增表保留，不删除历史数据。不需要修改外部测试网站或迁移其生产凭据。

## 13. 动态分组与渠道变化：运行契约

### 13.1 直接沿用本站关系，而非重新维护映射

源码事实：`model/ability.go` 的主键是 group/model/channel；AddAbilities、UpdateAbilities 依据渠道的 Models 和 Group 建立组合。`model/channel.go` 的 Update 会更新渠道后重建 abilities，状态更新另调用 UpdateAbilityStatus。当前这些外层步骤并非全部处于同一事务，不能把单次事件视为完整一致快照。

执行前取“数据库中渠道启用且支持该模型/组”与“enabled ability”的交集；发现短暂不一致仅延后该目标并在下一次对账修复派生订阅，不自行修改业务关系或停全站。测试侧 hook 在成功完成业务更新后触发；每 60 秒对账覆盖批量编辑、自动禁用、事件丢失和绕过接口的人工修改。直接数据库修改只能记录观察时间 observed_at，不能编造精确变更时间。

五种 revision 分开管理：topology_revision（组归属/业务启停）、execution_revision（地址、Key 版本、映射、参数、模型档位）、layout_revision（展示顺序）、control_revision（停止/恢复/排除）、presentation_revision（显示别名）。纯移动分组不必作废等价渠道结果；换 Key/模型映射必须建立新执行版本；纯改展示名称或排版不触发付费重测。

业务操作触发的订阅和当前结果失效目标时效为 5 秒，对账兜底为 60 秒；这不是上游返回新作品的保证。所有付费发送都先重查有效状态。当前结果 API 对成员做现时过滤，已关闭/移出的渠道不得因旧缓存还在而继续伪装为当前可选渠道。

### 13.2 四类核心场景的明确结果

| 事件 | 未发送任务 | 已在执行的任务 | 当前展示和后续轮次 |
| --- | --- | --- | --- |
| C1 被全局关闭，A 还有 C2/C3 | 撤销 C1，释放未发送预留；C2/C3 保留 | 尽力取消 C1 在途，其已发生费用保留；不取消别的渠道 | A 从 C2/C3 重新选图，缺位补它们的合法近期作品或占位；下轮继续 C2/C3 |
| C1 恢复业务启用 | 无人工停测限制时恢复已有启用组/model/profile 订阅 | 不重发关闭前的未知结果请求 | 当轮窗口允许时按补测限额加入，否则下一半小时参与；人工排除仍保留 |
| C1 同时属于 A/B，条件相同 | 合并为一份物理任务，绑定 A/B | 只执行一次，只有一个渠道限流占用 | 同一个 run 为 A/B 各自产生投影；各组排名独立，全站仅一份成本 |
| C1 同时属于 A/B，条件不同 | 按 medium/high、模型映射或请求上下文拆成两份 | 两份都受同渠道并发上限约束 | 标明不同测试档位，不交叉冒用成绩 |
| C1 从 A 移到 B | 撤销 A 订阅；为 B 建立订阅，同条件任务尽量合并 | 若只是归属变化、执行条件仍合法，已发请求可完成为渠道样本；不发布为 A 当前结果 | A 继续测剩余渠道；B 按新关系接续。A 的过去历史不搬到 B |
| C1 保留 A 并新增 B | 保留 A，增加 B；尚未发出的等价任务可直接共同订阅 | 已发送任务不会为 B 再复制发一次 | B 可显示本轮等价样本的“加入前参考”，下一轮成为 B 正式历史；A 不中断 |
| C1 从 A/B 中仅移出 A | 只撤销 A 订阅；B 仍需要就不撤销共享任务 | 共享任务为 B 继续，不能因 A 移出而误杀 | A 当前列表移除 C1，B 连续更新 |
| C1 换地址/Key/映射/参数 | 旧执行版本未发任务作废，创建新版本 | 尽力取消旧版；晚到结果只归旧版本 | 新版本重新积累基线；旧作品明确历史，不加入当前优选 |
| 某组仍有渠道，但该模型已无支持渠道 | 只暂停该 group/model 的派发 | 已发结果归旧关系历史 | 显示“该模型暂无可测渠道”，同组其他模型、其他分组继续 |
| 分组删除或合并 | 结束相关订阅，保留仍被其他组引用的任务 | 同上按剩余订阅与执行有效性处理 | 保存原组历史，默认从当前列表隐藏，不硬删结果 |

全局关闭后恢复不能自动复用关闭前尚未完成的试卷；组内出现坏渠道不会让整组永久进入“失败后不再调度”。超时/故障影响当次任务，下轮重新按当前有效配置调度；智商测试不会擅自重新启用业务已禁用渠道。

### 13.3 历史与现状不能互相篡改

“历史”按发送时合法订阅快照记录；“当前展示”按此刻有效成员过滤。两者有各自视图，避免移组后旧组历史整段消失或新组凭空多出几天历史。

新组在任务 dispatch 之前加入，可以进入本轮正式订阅快照。dispatch 之后加入，仅当本轮样本指纹等价、execution_revision 未变且渠道仍启用时作为“加入前参考”展示，显示测试时间及加入时间；不计入 B 加入后的覆盖/通过率。超过本轮的样本不冒充新组当前测试。

分组历史按 group-scoped public ID 读取，跨组共享内部 run ID 不暴露其他分组名称、真实渠道或私有结果。移出后仍允许通过当时公开组的历史投影查看已公开历史，但隐藏组、删除组的展示权限由当前可见策略决定。已下载截图无法通过隐藏开关追溯收回。

当前业务组标识是字符串，不能凭名字相近推断改名。已有 `model/group_rename.go` 接收明确重命名映射，处理 GroupRatio/API Key 等引用，并未在该函数统一修改全部渠道归属。稳定身份与迁移规则详见 13.6；历史快照保留当时名称，当前视图使用当前显示名称。

### 13.4 变更补测不破坏测试计划

1. 优先复用本轮已经排队/完成、条件相同的物理任务；绝不为了增加组归属重复付费。
2. 若变更导致已启用 group/model 当前没有任何可用样本，允许对一个有效成员安排“配置变更补测”，前提是未到本轮新生成截止（起点+2T/3）、未手动停止且有预留预算。
3. 变化合并窗口默认 30 秒。同 channel/model/profile 每计划轮次最多一次额外变更补测，频繁切换归属或参数不会循环触发；配额超过则下一计划轮次处理，换计划也保留原冷却。
4. 补测费用来自总预算内的变更预留（推荐最多 10%），不能加在总预算之外；补测原因单独记录，不拿答错作为补测理由。
5. 超过本轮新生成截止后发生变更，只更新成员与页面状态，下一计划轮次正常排队。不为追求立即出图抢占真实业务或无上限补测。

### 13.5 持续运行的边界与恢复

持续运行的工程承诺是：已启用范围随本站关系自动跟进；单渠道/单题型故障不阻断其他任务；按有效计划继续创建轮次；可恢复的基础设施故障消失后自动接续；所有暂停或缺失有明确原因和下一步。

它不等于在用户主动停止、预算耗尽、没有支持该模型的渠道、数据库不可用或全部上游拒绝请求时仍能产生真实成功结果。优先级为：人工停止 > 权限与预算/资源边界 > 自动连续运行。不能靠伪造数据、无限重试或擅自超额付费满足“必须进行”。

自动健康检查只做内部连接与队列检查，不额外调用付费模型。建议每 60 秒检查 worker/lease/对账时间；连续 90 秒无 worker 心跳、超过 120 秒未完成对账、连续两个周期某启用组无已完成单项时，在运维页提示。故障恢复后可继续；人工 stop 必须显式 resume 才能恢复，重启不会自动解除。

视觉评审宕机：逻辑题继续，规则图形继续，场景 PNG 安全生成后显示待评，评审任务按原题/原图恢复。渲染宕机：逻辑题继续；图形仅内部保存原文，公开端不执行原文。超过积压容量时仅暂停相关图形生成；恢复后先服务本轮，再在保留期与预算内补评历史，不重生成旧答案、不修改已封存历史的原发布版本，追加评审修订。

### 13.6 固定身份、显示改名与业务改名

代码事实：Channel 已有数字 Id 与独立 Name；Ability 的 Group、Channel.Group、GroupRatio 和 GroupOrder 仍以字符串名称关联。现有分组没有可直接沿用的全局固定 ID，不能声称“现在改名天然安全”。能力系统增加身份登记层，业务路由继续沿用现有模型，不以本功能为由全站重写分组架构。

| 对象或操作 | 关联规则 | 结果与设置如何保留 |
| --- | --- | --- |
| 渠道改 Name | 以 channel_id 关联，名称只展示 | 结果、停测、模型范围和匿名代号保留；同名渠道在后台用名称 + #ID 区分 |
| 分组改测试页显示别名 | 以 group_uid 关联，routing_key 不变 | 排序、排除、订阅和历史保留；别名只在能力页面生效，不能冒称全站已改名 |
| 业务分组正式改路由名称 | 以明确 old_key → new_key 操作承接同一 group_uid | 仅在合法迁移成立时更新当前路由绑定，保留旧名称时间区间与操作记录 |
| 删除渠道后新建同名渠道 | 使用新 channel_id | 不按名称继承旧对象结果或停测策略；原记录保留为历史 |
| 删除分组后新建同名分组 | 创建新 group_uid，旧身份归档 | 不继承旧身份历史/排序/排除；明确恢复原对象须独立恢复记录 |

首次登记为每个已发现的业务组分配固定 UID；控制接口、页面 key、测试排序、权限投影和结果引用统一使用 UID。路由名只在业务边界解析，显示名称不参与有效请求签名。默认没有自定义别名时展示当前路由名称；已设置别名时，后台同时展示“显示名称 / 当前路由名 / ID”，避免误认。用户端不暴露渠道真实名称、数据库 ID 或其他组私有身份。

正式改名必须携带可审计且幂等的 rename_operation_id，并验证新名称未被另一个活跃身份占用；合并不是改名，不能把两个组历史直接拼接。现有改名代码仅同步 Token.group、planned_subscription_group、token_route_steps 与 GroupRatio；实施时必须列全渠道 Group、abilities、展示元数据及其他受影响引用，扩展既有流程或明确分步迁移状态。不得仅看到 GroupRatio 改名就宣告全站迁移完成。

业务迁移未完成时保留同一身份，标记“关系迁移中”，只对已核实一致的绑定派发；不得同时把旧名和新名当作两个完整分组重复测。受影响订阅暂停的原因可见，其余分组继续。迁移记录与身份变更使用事务或可靠事件补偿，对账以 operation ID 幂等恢复；未知删除/新增仅提示待确认，不自动猜测继承。绕过接口在两次对账间删除又同名重建无法仅靠最终字符串可靠识别，必须接入生命周期事件；无证据时不承诺无损识别，也不自动重绑可疑历史。

纯显示改名不取消在途、不重测、不重置停测，也不改变历史分母。业务路由改名若影响动态请求头、参数表达式或实际请求上下文，则即使 group_uid 不变也需建立新 execution_revision；若已证明请求完全等价则继续复用。历史页面同时显示“当时名称”和需要时的“现名称”，不会倒改旧记录。

### 13.7 分组展示默认继承、别名与描述的独立编辑（V6）

本轮只读核对参考提交的 `controller/group.go`、`service/group.go`、`setting/user_usable_group.go`、`setting/group_metadata.go`、`setting/ratio_setting/group_ratio.go` 及前端组选择器，得到以下映射；这是真实代码来源，不新建人工维护的组配置副本。

| 页面信息 | 默认来源 | 测试后台允许的修改 |
| --- | --- | --- |
| 分组标题 | 业务分组的当前名称，即 API 返回的组 key | 测试页显示别名；不改变路由名称 |
| 分组说明 | 当前访问者有权读取的有效分组 desc | 继承本站说明 / 自定义测试页说明 / 不显示说明 |
| 分组倍率 | 现有售价 GroupRatio，经现行 GetUserGroupRatio 规则解析 | 只读继承，不提供另一份“展示倍率”输入框 |
| 图标 | GroupIconTypes 的当前配置与现有图标解析 | 首版继承；无值使用本站已有默认，不凭空添加认证标志 |
| 排序 | GroupOrder，未排序对象稳定追加 | 测试页独立排序；可恢复继承，不改变业务组顺序 |

当前 `GetUserGroupRatio` 已不使用旧的用户级 GroupGroupRatio，而直接取单层 GroupRatio。这里展示的是“分组倍率”，不是渠道成本倍率、模型最终单价、折扣承诺或测试成绩。模型定价/组模型覆盖/入口倍率等仍以现有计费系统为准。`GetGroupRatio` 在缺配置时会返回 1，展示必须额外做存在性检查：配置为 0 必须显示 ×0，明确配置为 1 显示 ×1；缺配置则标“倍率待配置”，不能把后备 1 伪装成已经设置。`auto` 是自动路由选择，不作为拥有固定渠道池和固定倍率的独立被测实体，不能给它编造一个 ×1。

用户卡片按照同一授权元数据投影返回标题、描述、倍率和图标；不能直接遍历全部 GroupRatio 暴露私有组。现有可用组含特殊可用组、有效订阅与虚拟会员组，继承描述须按现行服务逻辑解析，不能把某个管理员看到的 desc 固化给全部用户。自定义测试页说明是该组对其获授权访问者的统一说明，不扩大访问范围。

字段语义：`display_name=null` 表示继承；自定义名称去首尾空白后必须非空。说明用明确的 `description_mode`：inherit 实时读取来源；custom 保存非空纯文本；hidden 不渲染说明。建议别名上限 40 个 Unicode 码点、说明 160 个，最终以真实长文本布局验收调整；不接受 HTML、脚本或样式。恢复继承清除覆盖，之后跟随业务元数据变化。别名/说明按 group_uid 保存，渠道增删、移组和名称变化不丢失；正式业务改名仍须满足 13.6 的身份承接，不能按显示文字猜归属。

后台入口为“测试设置 → 展示与文案 → 分组展示”：列表显示业务分组、测试页名称、继承/自定义、实际倍率、说明来源和编辑按钮。编辑 Sheet 顶部保留只读业务名称及稳定身份，字段旁注明“用户端智商测试 → 对应分组卡片 → 标题/说明”，提供恢复继承和定位预览。倍率旁提供到本站现有分组倍率设置的导航，开发时复用已存在路由，不另设一个修改业务价格的测试接口。

别名/说明沿用文案的草稿—预览—应用版本，不增加第二套保存语义；其他立即生效的开关仍按 14.11 执行。业务名称、倍率、默认说明的源变更无需在测试页再次保存，按版本失效与对账自动跟随；已设置的别名/自定义说明继续保留。用户详情可查看“对应分组：<当前业务名称>”，只显示其已获授权的业务名称，帮助选择 API 分组，不暴露渠道 ID。历史题目、归属和计费快照不随当前别名/倍率重写。

## 14. 后台放在哪里、每个按钮究竟做什么

### 14.1 与现有设置顺序一致

Default 当前运维子项顺序为：系统行为 → 监控与警报 → SMTP 邮件 → Worker 代理 → 日志维护 → 性能 → 系统维护 → 使用教程 → 顶栏排序。新增“智商测试”放在“监控与警报”之后，其他原有顺序保持不变。

路由：`/system-settings/operations/capability-testing`；接入 `operations/section-meta.ts`、`operations/section-registry.tsx`、已有 `$section` 校验及 i18n。现有通用路由无需另造一级设置分类。管理页可复用 SettingsSection/SettingsPageFormActions，但控制状态走专用 capability API。

Classic 在 `components/settings/OperationSetting.jsx` 的 SettingsMonitoring 之后、SettingsCreditLimit 之前增加同名卡片，入口可滚动到卡片锚点。两主题使用同一后端配置和权限，不各保存一套开关。

管理入口为“系统设置 → 运维 → 智商测试”，内部使用“测试设置 / 运行记录”两个页签。测试设置按总控 → 分组、模型与渠道停测 → 题型与判分 → 展示与排序 → 费用与容量排列；运行记录独立成可筛选表格，不塞在长表单底部。渠道停测表放在范围区，提供全站渠道视图；总控的本轮数量/异常摘要可直接跳到运行记录对应筛选。

### 14.2 总控、显隐与排列的操作契约

| 操作 | 运行影响 | 用户端影响 | 生效与恢复 |
| --- | --- | --- | --- |
| 停止全部测试 | 停止新生成/重试/补测/评审，撤销排队，尽力中止在途 | 保留最近已发布结果，标“测试已停止”和真实时间 | 一次点击即提交、立即显示 stopping；worker 确认后 stopped；只能显式恢复 |
| 恢复测试 | 预检预算、目标和 worker 后恢复；已发送的未知请求不重放 | 正常展示更新进度 | 本轮窗口内只补未发送任务，否则下一半小时槽 |
| 隐藏测试（默认主操作） | 原子设置停止，撤销新生成/重试/补测/评审，尽力取消在途 | 隐藏所有普通用户入口、页面、结果/图片 API | 一键 hide_and_stop；界面先显示隐藏且停止中，待在途结束显示隐藏且已停止 |
| 仅隐藏、继续测试（明确的次级操作） | 保留当前运行状态；运行中仍会产生费用 | 同上隐藏所有普通用户访问 | 显示“后台仍测试，会产生费用”；若本来已停止，该操作不会把它启动 |
| 显示测试 | 不改变运行状态 | 恢复入口和权限允许的数据 | 若运行已停止，仍显示停止状态，不偷偷恢复付费 |
| 调整题型/分组/模型显示顺序 | 不改出题、调用优先级、渠道权重或判分 | 仅重排对应模块 | 拖拽或上下移动即时保存；失败回退并提示，可撤销上一步 |
| 恢复默认排序 | 不改运行 | 题型恢复默认，分组恢复继承本站 GroupOrder，模型按默认规则 | 不覆写全站原有 GroupOrder 或顶栏顺序 |
| 单独隐藏某组/模型/题型 | 默认只影响展示，后台继续执行 | 移除相应展示模块 | 界面明确“隐藏仍测试”；停测使用独立“参与测试”开关 |

总控开关必须在服务端执行，不是仅取消前端计时器。停止命令增加 control_revision，所有 workers 发送前核对当前版本；停止提交之后不得再批准新的派发许可，已获得许可或已到达上游的请求只能尽力取消，费用可能继续结算。API 返回未结束请求数；不能在尚未确认时假装所有请求已物理终止。

展示隐藏优先级高于全站/个人导航偏好，普通用户不能用直链绕过。隐藏后结果 API 返回一致的不可用响应并清除前端缓存；新访问的制品下载同样鉴权。能力制品默认不使用不可撤销的公开 CDN 长缓存；已打开页面收到设置 revision 后清空展示，已离线保存内容无法撤回。

后台修改统一 RootAuth，并记录操作者、时间、前后值、原因、control/layout revision；普通管理员是否授权运行控制沿用项目权限机制，不通过前端隐藏按钮代替后端授权。紧急停止是独立即时操作，不被未保存的其他表单修改阻塞。

主按钮“隐藏测试并停测”始终采用安全的默认组合，不记忆上次“仅隐藏”的选择而改变下次默认。次级菜单提供“仅隐藏、继续测试”，不摆两个文案相近但副作用不同的匿名开关。已经隐藏但仍运行时，主操作仍可切到隐藏且停止。再次“显示测试”不自动恢复；管理员在隐藏中显式恢复时，按钮旁提示“恢复后仅后台运行”。同组/模型的展示隐藏仍按对应标注执行，不暗中放大全局停止的范围。

这里的“全部测试”仅指本功能的生成、补测、重试与评审；不关闭业务渠道，不停止现有模型状态/可用性探针。隐藏中的管理员运行记录始终保留，不受普通用户导航偏好影响。

### 14.3 排序控制到哪个层级

三个独立展示序列：`task_order`（逻辑/规则图形/场景绘图）、`group_order`（固定 group_uid 列表）、`model_order[group_uid]`。每个支持拖动、上移/下移、恢复默认；手机和键盘用户也可操作，不只提供拖拽。

默认分组顺序继承现有 `setting/group_metadata.go` 的 GroupOrder，经当前 routing_key 解析为 group_uid；自定义顺序按 UID 持久化，只在能力页生效。未知新增项按全站顺序追加，旧项暂时隐藏不会丢失顺序；删除项清理投影但保留审计。改展示名称不改变排序，正式路由改名须同步或修复原展示元数据，不能改名后静默掉到末尾。

保存整组序列为一个事务，拒绝重复/未知 ID、循环或非法引用；使用 expected_layout_revision 避免两管理员互相覆盖。操作成功前显示“保存中”，失败恢复原排列。上移/下移是排序命令按钮，不是开关：按对象固定 ID 交换相邻两个完整行，名称、状态、说明和操作区一起移动，首行不能上移、尾行不能下移。React 使用固定 ID 作为 key，不用行索引；焦点留在被移动对象，短暂整行高亮/位移动画说明移到了哪里，减少动态效果偏好下直接完成换位。服务器保存失败则整行复位并报错；点击期间防重复保存，不能只交换箭头的禁用状态造成“按钮开关”的观感。

展示顺序不是执行顺序。后台单列只读说明“各组公平轮转”；不提供通过首页排版偷偷优先消耗某组预算的机制。真正暂停某题型会创建下一轮新 suite/profile 版本，不能用隐藏按钮改变成绩分母。

### 14.4 范围与费用区的具体字段

- 分组列表自动读取本站：参与测试、对用户显示、继承/覆盖测试档位、模型选择、自动跟随成员、当前有效渠道数、本轮完成数、共享省下的重复任务数。
- 渠道只作为该组展开的派生列表展示，默认无需手工维护；可以显式排除特定 channel/model 并备注，排除项不会在对账时被重新加回。取消排除自动接续，不改业务渠道状态。
- 所有新增组/渠道/模型自动同步到清单；符合已设继承规则的组和成员自动开测，未知模型标原因，不扩大未授权范围；自动化规则变更时预览影响数量。
- 题型：参与测试与展示可见两个字段；题库/评审版本、推理档位、场景样本数、超时与重试上限；周期/时段按第 6.1 节调整，不提供任意秒级输入。
- 费用：日总预算、当前预留/已消耗/未知费用、变更补测预留、生成/评审成本估算、队列容量。基础运行预算不足时只阻止新增付费，不能把停止标志改成人工 stop。
- 预览：只生成题目与模拟布局，不调用模型；“真实手动测试”单独按钮，显示最大预算消耗，遵守全局停止与预算。

### 14.5 单渠道停测：绝不等于关闭业务渠道

渠道行分列“业务状态”和“智商测试状态”，显示名称 + #ID、所属分组、有效停测原因、最近轮次与操作。入口集中在智商测试设置；现有渠道管理如增加快捷入口，仅跳转到对应 ID 的测试设置，不把两个状态合成一个开关。

| 控件 | 范围 | 共享渠道的处理 |
| --- | --- | --- |
| 此渠道全站停测 / 恢复此渠道测试 | 指定 channel_id 在所有组的智商测试；默认全部模型/profile | A/B 都停；恢复仅解除这条限制，不解除各组自己的停测 |
| 仅在本分组停测 / 恢复本分组测试 | 指定 group_uid + channel_id | A 停不影响 B；B 仍需时保留共享任务，A 不再获取当前投影 |
| 高级：仅停某模型或档位 | 在上述明确作用域下限定 model/profile | 其他模型/档位继续；高级限制折叠显示，恢复不清除其他限制 |
| 批量停测 / 恢复 | 勾选固定 ID，提交前展示范围与影响数量 | 不提供含糊的“禁用所选”；使用同一规则与审计 |

推荐采用持久化排除规则，明确拒绝优先：全局人工停止、业务渠道禁用、渠道全站排除、分组/模型/profile 排除、未纳入范围、预算/资源阻塞任一成立均不可派发。恢复只清除所选规则；若还有其他原因，显示“本项限制已解除，仍因……未测试”，不假报运行中。业务关闭后重新启用、渠道改名、移入新组、自动对账、预算跨日和进程重启都不能清除人工全站排除；分组内排除固定绑定原 UID，移出再移回仍有效，移入另一组不会把 A 的排除误搬给 B。

停测提交递增 control_revision，发送许可和发布时都检查有效策略。撤销对应订阅的排队/重试/补测/未发评审，释放未使用预算；仍有其他合法订阅时保留共享任务。最后一个合法订阅消失时尽力取消在途；已发生费用照常记录，晚到结果仅归内部证据/历史，不重新进入被排除组当前优选。全站停测该渠道时也禁止为其他组新建它的任务；独立评审服务的运维停用应另有 judge 控件，不与被测渠道身份混用。

恢复按 13.4 的限额接续当前窗口或下一轮，不重新抽样刷高分，也不重放未知付费请求。当前三格从仍参与测试的渠道重新选取，缺位按 5.1 补近期作品；全部被人为排除时用户显示“测试计划已暂停，可查看历史结果”，后台保留明确停测原因，不判零分或偷偷启用渠道。停止全部仍按 14.2 保留最近快照并标暂停；单渠道排除移除当前优选。

所有这些接口只写 capability 控制与派生数据，不修改 Channel.Status、权重、Key、业务归属或原有可用性监测/canary 开关。控制表单保存、改名和排序均不得误触发这些业务写接口。

### 14.7 管理员在哪里看真实调用与测试数据

固定入口：“系统设置 → 运维 → 智商测试 → 运行记录”。默认是实测记录；模拟演示仅在独立 fixture 预览模式出现，标记“模拟数据”，不能混入生产记录表、正式排名或用量合计。使用日志仍展示原有用户消费；测试记录复用其表格、筛选、分页和详情交互，但使用独立数据源，不通过写用户消费记录来凑可见性。

列表每行是一个题型的 run，可按轮次聚合。列包括：计划/实际开始时间、组/渠道、请求模型、实际协议与档位、题型、执行阶段、判分、耗时、tokens（来源标记）、费用（币种/估算状态）、来源（自动/手动/验收）与详情。共享样本一条物理调用关联多个合法分组，列表展开可看归属，不重复累计 tokens/费用；生成与视觉评审各自单列来源和费用。

详情用现有 Sheet/Drawer，分四区：

1. **调用过程**：round/run/attempt/trace ID、各阶段时间、选中的 channel_id 与匿名 Key slot、脱敏 endpoint/协议、请求模型、映射后发送模型、上游返回的模型名称、有效请求指纹、重试/取消/跳过原因。上游回报模型字段只标“上游声明”，不能据此保证实际模型身份。
2. **题目与回答**：冻结 prompt、标准答案/求解器版本、有效参数、流式完成信号、可见回答、输出是否截断、usage 原始字段及来源。不索取或推断隐藏思维链；不输出 Authorization、Cookie、DSN、密钥或未经脱敏的错误正文。
3. **判分与作品**：每道答案比较、图形规则证据、渲染 PNG、场景评审逐项结论及版本、不确定原因、制品哈希；可从用户卡片追溯到同一结果和发布 revision。管理员原文也转义显示，SVG 不直接注入页面执行。
4. **费用与归属**：每个 attempt 的预留/消耗/待核对金额、输入/输出/缓存/推理用量来源、价格版本、共享分组、订阅时间区间、该样本是否进入前三及排除原因。仅有估算时明确“估算”，usage 缺失显示“未知/待核对”，没有发送不能记为真实上游调用。

状态要区分 planned/queued（未调用）、dispatching（已获发送许可）、generating、response_complete、grading、published，以及 failed/cancel_requested/cancelled/outcome_unknown/skipped。HTTP 200 不能自动变成“答题通过”，收到第一段 SSE 不代表完成；请求已发但无证据确认完成不能伪称未计费。评审/渲染故障与被测模型答错分开，失败和未完成都保留记录，不能仅保留好看的前三。

日志在预留与派发阶段就落库，完成/错误/取消追加事件；进程崩溃后通过 dispatch 标记和上游可用的 request ID 对账。日志持久化失败则停止新的付费派发，已有未知请求不盲目补发。所有管理查询与制品访问由服务端鉴权、脱敏、分页和限流；隐藏用户页不会隐藏这些管理证据。默认管理员只读，修改运行控制仍按 RootAuth；无授权管理员不能看到其他受限凭据或配置。

| --- | --- | --- |
| 页面及入口 | 默认隐藏并停止 / 仅隐藏 / 显示 / 恢复 | 服务端执行；显示不自动开测；停止不影响业务 |

### 14.9 分组—模型—渠道的自动同步和适配链路

后台首次载入自动发现本站全部组配置、渠道及其声明模型，展示“已发现/可执行/未纳入/已排除/需配置”的数量。业务组目录与渠道 Group/Models 用于发现全集，enabled abilities 与数据库渠道启用/成员交集用于执行许可；缺失 abilities、孤立组和短暂配置不一致也要列在后台，不能因不进入执行列表而被悄悄漏掉。模型名及映射区分，不能把模型目录笛卡尔积自动当成所有渠道支持。

每条关系都有可展开的适配链：固定 group_uid → 当前 routing_key → 请求模型 → channel_id 与启用状态 → endpoint/协议适配器 → 映射后模型 → 有效参数/推理档位/非敏感客户端上下文 → Key slot 选择 → 套题与输出限制 → 渲染/判分支持 → 费用许可 → 调度许可。后台显示各节点的实际值、继承来源与验证时间；需要秘密的节点只显示已配置与版本，不展示值。

套题和默认档位按全局 → 分组/模型覆盖继承；渠道自己的真实模型映射、地址和覆盖设置仍由业务配置决定。测试侧只有显式、受控的 profile 可以补必要测试上下文，不为跑通测试修改生产映射/Key/业务分组。无法复现上下文、不支持文本/SVG、无视觉评审支持或价格未知分别有原因码，不当作低智商或渠道业务失效。

业务增改事件触发派生同步，目标 5 秒；每 60 秒全量/增量对账兜底，启动时做一次恢复对账。新增组自动登记 UID 并继承新组策略；新增渠道自动读取其所有合法分组与模型，不要求重新绑定。自动开测受已批准模型范围、适配档位、成本和总预算限制；新模型自动显示但未知规则不会凭名字猜测。所有自动加入/排除决策写审计，与最后同步时间、延迟/故障和待处理原因在后台可见。

删除/移组/关闭按原契约撤销订阅、保留历史；改名按固定身份承接，异常记录不串组。对账失败不拿旧关系无限发请求，发送许可重查数据库。后台“立即同步”仅用于故障诊断，可限流且不产生付费请求；正常增删无需按它。执行范围与用户可见范围分别继承，自动发现私有组绝不自动公开。

#### 符合本站 new-api 设置结构的编辑界面

- 已核对 Default 的 `features/system-settings/maintenance/notice-section.tsx` 使用 `SettingsSection`、`SettingsForm`、React Hook Form/Zod、FormLabel/Textarea/FormMessage 及 `SettingsPageFormActions`；`components/settings-form-layout.tsx` 提供 `SettingsControlGroup`、双列布局与全宽字段。文案编辑沿用这些组件：短标题使用 Input，正文使用 Textarea；位置说明放在字段下方，帮助文字使用 muted 样式，不做另一个 CMS 界面。
- 按“首页概览 / 测试方法 / 作品与历史 / 页面补充”组织字段，常用项先展示，六章长文按章节进入编辑，避免后台也变成过长展开页。每项有清楚的正式中文标签，不能只写“文案 1”“Slogan”“caption_key”。
- “定位预览”使用真实用户组件渲染隔离草稿，并高亮对应位置；显示正在编辑的字段名称、语言和模拟/真实数据来源。支持明暗与桌面/手机预览。示例：修改“概览标题”时预览直接定位顶部卡片标题，不要求管理员猜测。隐藏中的模块标明“当前前台未展示”，允许预览但不擅自显示或开启测试。
- 保存与恢复采用现有页级操作区和反馈模式。按钮明确为“保存草稿”“预览”“应用文案”；字段可“恢复此项默认”，区块可“恢复全部默认”。“撤销未保存修改”与“恢复默认”分开：前者恢复上次加载值，后者清除自定义覆盖并进入草稿，应用后才影响用户。
- 离开未保存编辑时沿用现有 dirty guard；保存中防重复提交，失败保留输入，错误靠近具体字段。成功显示应用时间和版本，不只给模糊 Toast。手机输入框不拥挤，定位预览返回后保留编辑内容与焦点。

#### 配置与真实性边界

文案使用固定 `slot_key + locale` 标识，例如 `overview.title`、`overview.description`、`overview.paused_description`、`method.trigger_label`、`method.title`、`method.introduction`、`method.sections.<固定章节ID>.title/description`、`gallery.description`、`history.description`、`footer.description`。章节 ID 不随排序和改名变化。作为 `capability_presentation` 的文案覆盖存储，复用既有草稿/发布 API，不在前端硬编码管理员修改、不写进全站 Notice，也不复制第二份渠道/分组配置。

每项记录使用默认或自定义、覆盖文本、语言、最近操作者与时间；必需字段空白拒绝保存，选填字段允许显式留空，恢复默认清除覆盖。建议标题上限 40 字、按钮 24 字、摘要 240 字、章节解释 2000 字，按 Unicode 码点统一前后端计数，长英文及中文均需布局预览；这些为可调整校验默认值，不截断管理员已输入的内容。纯文本输入、服务端校验、前端转义，不支持 HTML/JS/CSS 或任意插值表达式。

时间、实际测试周期、评分、样本数、来源、模型与档位、结果状态和方法版本均为只读系统字段。文案只能编辑标题与补充解释；六章中的实际题型表、判分规则、来源含义和适用范围保留系统说明，不因删除补充文字而消失。用户已禁止的短语作为明确文案校验项；其余文字是否与事实矛盾须在预览中由管理员核对，不能声称自动校验能理解并保证所有自由文本的真实性。

按站内支持语言编辑覆盖；缺少某语言自定义时使用该语言的内置正式文案，再遵循现有 i18n 回退，不把英文页面自动换成整段中文或擅自调用翻译模型。Default 与 Classic 消费同一生效版本，各用原组件布局；主题切换不另存一份文案。新增字段使用默认值，版本升级不会静默覆盖已保存的自定义内容。

写入与应用沿用本方案 RootAuth 和后端授权。应用在服务端原子切换完整文案发布版本，携带 expected_presentation_revision；并发冲突返回 409，保留双方草稿供比较，不能覆盖别人刚保存的内容。保存草稿不会更改用户页；应用失败继续使用上一生效版本。记录操作者、前后值、语言、时间与版本；可恢复上一版文案，但不会恢复运行、预算、权限、排序或测试配置。旧轮次的实际评分方法版本不随当前宣传文字改写。

文案更新仅刷新对应展示缓存，不重新出题、不触发模型调用、不修改业务渠道。公开接口只返回生效且当前用户有权限阅读的字段；草稿、审计与作者信息仅管理员可见。隐藏页面时仍执行原有权限检查，定位预览不能成为公开绕过入口。

验收包括：上述字段逐一改文案并定位正确；必填为空/选填留空/超长/脚本输入；中英文回退；改名或排序后章节仍对应；草稿与线上隔离；两管理员冲突；保存失败与撤销；恢复默认/上一版；停测或隐藏时修改不启用功能；文案更新零新增测试调用；Default/Classic 双主题与窄屏完整显示。后台编辑器尚未实现，本节是正式实施与验收契约。

### 14.11 后台保存到前端/执行器生效的完整契约（V6）

每项设置必须注册固定字段、后端校验、持久化位置、生效消费者、影响时点和验收项。前端本地 state、成功 Toast 或 HTTP 200 都不等于生效；只有业务响应成功且权威配置可读回，才标“已保存”。需要发布的字段继续区分“草稿已保存 / 已应用”；需要执行器应用的控制继续显示“正在生效 / 已生效 / 部分节点未确认”。不承诺可以知道所有离线浏览器已更新。

| 设置族 | 持久化及生效时点 | 必须观察到的改变 |
| --- | --- | --- |
| 全局停止/恢复、单渠道/组/模型排除 | control_revision 原子提交；发送许可读取权威控制，取消通知驱动在途收尾 | 新派发受限、队列与运行记录有原因；前端按策略更新；不改变业务渠道状态 |
| 隐藏并停止 / 仅隐藏 / 显示 | hide_and_stop 同一事务提交可见与运行状态；服务端访问控制即时使用新状态 | 导航、页面、详情、图片的新请求一并受控；show_only 不开测；管理预览需独立权限 |
| 别名、说明、重点文案 | 草稿不公开，应用时原子生成 presentation_revision | 用户真实组件显示发布值，刷新/重新登录后仍一致；恢复继承后跟随本站元数据 |
| 模块/组/模型显隐、作品数量、近期策略、默认筛选 | 展示配置发布后生效，不触发生成 | 正式接口投影与组件一致；无结果用真实空态；不伪造第三个来源 |
| 整行排序 | layout 接口原子保存顺序及版本，立即读回 | 列表整体换位，刷新保留，其他字段与对象不串位；不改变派发优先级 |
| 自定义周期、时区、运行日/时段 | schedule_revision 带明确 effective_at，由调度器确认 | 下一执行时刻与未来五次计划一致，前端说明同步；不改已发任务和历史，不补发或隐式恢复 |
| 题型、profile、评审与预算 | 新执行/suite/评审版本；默认下一轮使用，紧缩预算即时阻止新增许可 | 管理端标注生效轮次；历史继续使用原规则，新结果引用新版本；用户方法说明匹配所查看样本 |
| 业务组名称/默认描述/图标/倍率 | 读取既有权威元数据，变更事件及周期对账失效缓存 | 继承字段自动更新，自定义覆盖保留；倍率零值/缺失正确区分；不重测、不改历史费用 |
| 刷新频率、详情/方法/历史功能开关 | 展示版本发布；刷新为读取行为 | 对应控件、内容及定时读取真正变化，组件卸载释放计时器；不新增模型调用 |

保存流程为：服务端权限与字段校验 → expected_revision 防并发覆盖 → 事务写配置与变更事件 → 返回已提交快照/生效时间 → 通知相关缓存、调度器和公开投影 → 管理端读回并显示确认状态。事务 outbox 或等效可靠补偿保留事件；Redis 通知只是加速，丢通知通过数据库版本对账恢复。运行控制无法取得足够新的权威状态时拒绝新付费派发，不能无限沿用旧的“允许运行”。已获许可/已发送任务按在途取消规则记录，不虚称网络调用可原子撤回。

前端使用本站查询缓存机制，保存成功后失效相应 query 并读回；附版本比较，较旧请求后返回不能覆盖较新设置。公开组数据包含授权范围与版本，缓存必须按访问权限隔离。打开页面恢复焦点/会话变化时重取权限及控制；前端作品刷新可手动，但可见性控制使用独立轻量刷新，不能因选了“手动刷新作品”而永久显示已隐藏模块。已下载到用户设备的图像无法远程撤回，关闭的是后续访问；缓存响应采用受保护资源策略。

拟定传播验收目标：正常在线管理端保存读回后立即反映；拓扑/元数据事件路径 5 秒内可观察，60 秒对账兜底；已打开用户页控制刷新不超过 30 秒（作品刷新仍可自定义），离线/后台休眠页面恢复时重新获取。以上是待实测目标，不是当前已实现 SLA。权限和停测不能依赖前端刷新周期：每个新服务端访问/发送许可都执行当前规则。

若存储或发布失败，保留管理员草稿并提示具体错误，用户继续看到上一生效版本。版本冲突返回 409 并提供刷新比较，不静默覆盖。节点未确认时提供节点与原因，不给虚假的“全部生效”；worker 恢复后先同步版本再领任务。主题/端别仅改变渲染，Default/Classic 读取同一配置源，不各存一份开关。

验收对矩阵每行执行“修改 → 保存/应用 → 服务端读回 → 必要的 worker 确认 → 真实用户权限接口 → 正式组件变化 → 刷新后保留”，记录各端 revision 与截图/请求证据。另覆盖写入失败、HTTP 200 但业务失败、并发冲突、乱序响应、缓存失效丢失、节点重启、旧前端包和隐藏期间编辑；展示类修改的模型调用增量必须为 0。

### 15.1 用户页结构

```text

最近测试时间 · 下次计划时间 · 测试方法（可展开）
方法摘要：通过逻辑推理与绘图任务，持续观察模型的任务完成表现。

分组 A · 模型 M · 标准推理             本轮已评估 2/3

样本 A · 查看详情   样本 B · 查看详情   样本 A · 查看详情
-------------------- 分项表现与历史 --------------------
逻辑题    46/48 道可判定题目正确   ▰▰▱▰▰…（点击具体轮次）
```

每组顺序固定为作品在上、数据在下，移动端也按这个顺序阅读。借鉴参考图的筛选、更新时间、作品卡片与详情，不照抄按账号铺满六列的布局；本站围绕分组/模型/档位组织。数据默认展开，可按后台配置折叠；首屏突出真实作品，不把大量诊断信息摆在图片之前。

默认 30 分钟计划的 24h 显示 48 个轮次格，3d/7d 按天分行；其他周期/窗口按当时 schedule 快照的实际计划格数生成。改间隔的分界处标注，未安排时段留空，不把 60 分钟结果复制成两个 30 分钟样本；手机按天/横向浏览。颜色与文字/图标并用：达标、部分达标、待评审、本轮未完成、暂停期间；未启用不计失败。

每个时间格代表该组当轮该题型全部合法主测样本，不只看前三；浮层显示“3 个来源：2 个满足要求，1 个未满足”，可展开实际证据。率的分母取可判定题目并显示计划数/缺失数，时间窗口及样本范围不可省略；近期/补充/同一作品补位不计入本轮主测分母。跨组共享在组内一次，全站按物理 run 去重。

顶部可显示“已更新的分组”“最近轮次”“正在评审”，不把精选图的成绩包装成全站平均智力。逻辑正确率＝正确题目数／可判定题目数，同时显示覆盖情况＝可判定题目数／总计划题目数及未完成数；两者不能混称正确率。可判定为零显示“暂无可判定结果”，不显示 0% 或 100%；统计范围固定且不以未知结果作零或一。

### 15.2 点击色块或作品的详情

桌面使用现有 Dialog/Sheet 扩展为大图优先详情：顶部只放标题、模型、真实时间、来源标签和关闭按钮；主区左侧作品（约 60%），右侧题目/逐项结果（约 40%），窄屏改为图在上、结果在下。画布 contain 完整显示，不裁切关键要求；支持适应窗口/原尺寸、前后作品、Esc 关闭、键盘焦点回到原卡。浏览器若放大不得截断关闭按钮。逻辑题详情则答案对照在前，不塞无关图片。

右侧默认“任务要求 / 逐项结果 / 测试信息”，优先展示可理解的证据；原始可见回答与方法版本放折叠区。题型切换必须对应具体同一试卷的真实 artifact；历史作品不挂本轮分数。来源是近期/补充/复用时清楚标明；sample_id/run ID 等调试项在管理详情，不堆给用户。原始回答转义，图片沙箱策略不因大图预览放宽。

点击色块先选该轮样本再查看题目，点击作品直接进入该图记录。每次打开都以公开投影 ID 查询并校验当前权限，不能由匿名渠道代号拼管理地址。只读放大、翻页、筛选、下载和刷新都不触发付费；生成重测只在后台受控操作。

### 15.3 状态变化的可见反馈

- C1 关闭：当前卡片移除它，其他成员继续，三格按剩余结果补位；历史色块保持。
- A→B：A 当前卡片重排，B 出现参考或“等待本轮结果”，页面不要求运营者手工重绑。
- 视觉评审不可用：逻辑时间线继续，场景图标待评，整个页面不变成加载失败。
- 停止全部：可见页面保留历史，倒计时改成“已停止”；点击刷新不恢复任务。
- 隐藏全部：主操作默认隐藏并停止，普通用户导航/直链/数据访问均不可见；只有明确选“仅隐藏”才保留后台运行，管理员看到实际状态与在途数量。
- 排序：即时预览，后台保存后所有用户采用新顺序，运行中的任务、历史排名和计费不变。

页面使用本站现有字体、卡片、暗色和组件体系。缩略图懒加载、历史分页，列表接口只传摘要；不一次传回所有 SVG。刷新频率与测试频率分别显示，避免误以为每次刷新都花钱测试。

### 15.5 专业、面向用户且有利于本站的表达

页面方法摘要建议：“通过逻辑推理、规则图形和场景绘图任务，持续观察模型的任务完成表现。优先呈现本轮表现较好的样本，点击作品可查看原题与评分依据。”公开的是可核对的服务能力，强调精选、持续测试和透明证据；不暗示精选成绩代表全部渠道，更不靠移除失败历史制造全通过印象。

| 用户看到的场景 | 建议文案 | 始终保留的事实 |
| --- | --- | --- |
| 当轮完成且入选 | 本轮精选 | 真实测试时间、来源、题目/分项成绩 |
| 历史补位 | 近期作品 | 实际旧时间；不列为本轮独立渠道 |
| 额外真实生成 | 补充作品 | 对应题目、主测之外的样本身份 |
| 复制同一图 | 同一作品 | 来源代号及同一个原结果，不换成“多源验证” |
| 已生成未评分 | 待评审 | 已生成时间；不提前标达标 |
| 当前正在执行 | 本轮结果更新中 | 实际运行状态及最近完成时间 |
| 执行终止没有有效结果 | 本轮未形成有效结果 | 真实缺失，不能长期伪装“正在测试”；技术原因留后台 |
| 人工停止 | 测试计划已暂停，可查看历史结果 | 真实最近时间，不显示虚构倒计时 |
| 答错或不符合要求 | 本题未通过 / 部分要求未满足 | 原题、实际回答、逐项依据；不直接断言降智或模型造假 |

完整“测试方法”包含：测试对象和适用模型、三题型与随机/基准题、当前周期及运行时段、主测与补充样本、判分方式/评审版本、不确定处理、精选与近期策略、去重统计范围、成绩解释边界、历史保留及更新时间。固定事实从配置/结果生成，可编辑的仅是标题/解释文案；方法变更版本化，不回改旧轮次依据。试卷难度和不同模型档位不能合并成伪精确 IQ 总分。

用户再次强调专业体系解释为必交项，不能只有一句宣传语或一个问号 Tooltip。正式模块标题为“测试方法与评分说明”，首页精简摘要与阅读入口，点击后打开独立六章节面板，不在作品列表里展开整篇长文；作品详情可定位到对应题型说明，手机通过章节选择器逐节阅读。沿用站内卡片、Dialog、Tabs、ScrollArea、表格与语义主题色；具体布局和交互见 15.7。

| 专业信息层 | 用户阅读内容与推荐表述 | 实际依据与 UI 约束 |
| --- | --- | --- |
| 首屏价值摘要 | “持续测试，让模型表现有据可查。通过逻辑推理与绘图任务观察任务完成表现，精选作品可查看原题与评分依据。” | 正式启用后才能陈述持续运行；已停测改为“测试计划已暂停，可查看历史结果”；演示明确非实测 |
| 对象与可比范围 | 按分组、模型、推理档位分别呈现；SVG 图形是文本模型输出的绘图代码 | 展示请求模型与实际测试配置，不承诺已识别真实上游模型；不适用模型另列，不判零 |
| 三类任务与评分 | 逻辑两题逐题 0/1，规则图形五项各 0/1，场景要求六项各 0/1；美观另列 | 分母、题型开关和 rubric 来自当前 suite；抽检/人工复核标识如实；未评不显示 0 分或通过 |
| 试题生成与公平性 | 基准题观察连续变化，随机题使用受控模板和可复现参数；同轮同档位用同卷比较 | 不用随机生成的无解题做判据；试卷/求解器版本、题目种子可追溯，模型配置变化分段 |
| 完整测试链路 | 按计划出题 → 对应渠道与模型作答 → 保存回答和作品 → 核验要求 → 发布结果 | 用户看五步简图与解释；后台对应每步实际事件/状态/费用，不展示虚构进度动画 |
| 精选与统计 | “优先呈现任务完成表现较好的样本”；本轮、近期、补充、复用分别标识 | 主测排名正确性优先；画廊不是全量平均，重复/补充/历史不增加本轮主测分母 |
| 证据与更新 | 原题、实际回答/图片、逐项依据、实际时间与方法版本；显示当前计划及最近完成时间 | 时间由结果生成，最近完成不能取页面打开时间；有后台运行计划不等于已经完成测试 |
| 结果解释 | “本题未通过”是该题结论；持续同条件结果用于观察变化，单次分数不代表完整模型能力 | 测试名不包装为标准化人类 IQ；不使用“官方认证”“绝对满血”“答错即模型造假”等无依据结论 |

标题与解释可编辑，评分数值、分母、时间、来源、方法版本由服务端生成且不可改写。预览/发布检查当前可见题型、运行状态、画廊策略、统计范围与文案是否一致；关键配置改变时同步生成说明版本。切换历史轮次须展示当时的方法，不能拿新 rubric 解释旧成绩。补充信息可以包括真实已更新分组数、已覆盖模型数和最近完成轮次，但要明确去重范围与时间；不加入用户已经排除的请求成功率板块。

专业说明的验收包括：初次无数据、部分结果待评、全部暂停、仅隐藏继续运行、自定义 45 分钟、单渠道三张近期作品、修改题型/评审版本、暗色与移动端。逐一核对摘要、方法表、图例、详情与后台实际记录一致；正式运行前不把计划中的机制写成已验证事实。

对管理方有利的做法是首屏突出真实优选、稳定的更新节奏和可复核作品，详细诊断留在后台；用户仍能通过测试方法/历史理解样本范围。开启关闭展示模块时同步调整相关说明，不能隐藏全部差样本却保留“全量通过率”等不实表述。

### 15.6 白色与黑色主题的完整适配

Default 复用实际 theme.css/theme-presets 的 background/card/popover/foreground/muted/border/primary 及 success/warning/destructive/info，Classic 用现有 Semi token；图标保持现有体系。列表、筛选、按钮、表格、状态、骨架、空态、Tooltip、弹层、滚动容器和方法区一起切换，不只改页面背景。普通文本至少 4.5:1、控件边界/焦点至少 3:1，并配文字/图标，不让颜色成为唯一状态依据。

生成的 PNG/SVG 属于证据，切暗色时不反色、不重配颜色、不加滤镜。透明画布沿用评分时冻结的背景并显示独立中性图框，保证用户看到的颜色/遮挡与判分图一致；主题只改变周围 UI。屏幕宽度改变使用 contain，不裁掉标准答案或图中物体。

验收覆盖明/暗两套的用户列表/详情/方法、后台六区/运行记录、禁用/hover/focus/保存失败/隐藏状态，桌面与手机均检查。模拟页的主题效果仅是静态示意；真实组件内截图/键盘与触屏验收仍是 G5 必交证据。

### 15.7 长说明的渐进阅读与首页质感（V5.1）

针对用户 P1“展开过长但全部内容保留”，专业说明保持一份内容源，改为“摘要卡 → 六章节阅读面板 → 具体证据”。主页面不内嵌整篇文章，也不靠缩小字号或截断内容控制长度。

- 首页入口：“测试方法与评分说明”，明确为可点击按钮。打开不会改变作品列表布局或位置。桌面面板建议最大宽 920px、高度不超过 86dvh，保留站内弹层样式；固定标题/关闭按钮，左侧章节导航，右侧单一正文滚动区。短章正常留白，不为填满面板增加重复文案。
- 保留六节全文及原评分表：对象与评分、从题目到证据、精选与来源、如何阅读结果、追溯与比较、结果的含义。每次显示一节，提供上一节/下一节和章节位置；关闭后再次打开保留本次会话选择的章节。正式后端方法数据不因分章而分散手工维护。
- 手机为同一个阅读器的窄屏布局：顶部选择章节、下方正文、底部翻节；不挤六个横排标签，也不要求同时操作多层纵向滚动。面板不超过 92dvh，200% 缩放、320px 窄屏下关闭按钮仍可达；评分表独立横向滚动，不撑宽全页。
- 支持 Esc 关闭、焦点约束与返回阅读入口；桌面章节支持上下方向键、Home/End，选中态有文字与形态变化。采用本站 focus-visible，不能为消除截图中的蓝框把焦点可见性删掉。切章节后的正文从顶部读，背景页面不可滚动。
- 方法开关、页面隐藏、权限撤销后关闭已打开面板并清理相应数据；停止测试仅更新真实状态与计划文案，历史说明仍可读。所有阅读、翻节与主题切换均为只读，不触发付费调用。

针对用户 P2“基于本站的高质量感”，摘要卡采用三层信息：18px/600 的模块标题、14px/1.75 的简短摘要、12px 的底部计划字段；移动端标题可收至 16px，正文保持易读。桌面阅读入口位于右侧，窄屏自然移至摘要下方。V5.2 正式标题、摘要和字段按 15.8 统一；底部以“测试周期 / 运行时段”标签和值展示，不放评分口诀。完整评分解释保留在阅读面板。

视觉依据为最新已核对源码的 `web/default/src/components/ui/dialog.tsx`、`tabs.tsx` 和 `features/dashboard/components/overview/announcement-detail-dialog.tsx`：复用字体、12px 圆角、细边界、Popover/Card/Muted 色阶与克制弹层阴影，不替换全站字体/图标。正式版直接组合站内组件；静态演示仅表达相同的信息层级。Classic 使用对应 Semi 组件实现同一阅读结构。

验收须将摘要卡与本站模型状态/设置页面并排比较，覆盖明暗、桌面/手机、200% 缩放、长自定义时段、停测、键盘和章节切换。全文六节及评分表与改版前逐项核对；开启说明后作品列表位置不变，关闭回原入口，不能丢专业说明或改写真实评分。当前模拟页的结构/状态检查不代替真实浏览器的视觉与无障碍验收。

### 15.8 正式用户文案与信息呈现规范（V5.2）

用户明确禁止“正确性优先 · 美观另评”出现在正式用户前端。此规则覆盖所有语言、首页、卡片、提示、弹层和辅助朗读文字；这类内部取舍口号不改写为另一个短句继续上屏。已有章节中的历史文案建议如有差异，以本节为准。后台可以准确说明操作范围和费用，用户页提供对阅读结果有用的信息；不能靠模糊文案掩盖停测、未完成、历史引用或真实不达标结果。

#### 正式表述清单

| 展示位置 | 推荐正式文案 | 信息规则 |
| --- | --- | --- |
| 首页说明标题 | 测试概览 | 作为功能标题，不采用宣传口号 |
| 首页摘要 | 查看模型在逻辑推理与图形任务中的测试结果，以及对应的题目、评分依据和历史记录。 | 未开展实测时使用真实空态；演示另标模拟数据 |
| 计划字段 | 测试周期：每 30 分钟；运行时段：全天（北京时间） | 标签和值分层，数据从配置生成；暂停独立标明 |
| 说明入口 | 测试方法与评分说明 | 使用站内按钮和向右指示，不用表示外链的箭头 |
| 方法导语 | 了解测试范围、评分标准、作品筛选方式及结果解读。 | 六章节内容完整保留，按主题阅读 |
| 方法章节 | 测试对象与任务；测试流程与题目设计；作品筛选与来源说明；测试状态与结果解读；记录追溯与统计范围；评估范围与适用说明 | 标题与导航对应，不用“先比什么”“怎么补位”等内部讨论措辞 |
| 作品与详情 | 本轮精选 / 近期作品 / 补充作品 / 参考作品 / 同一测试作品；查看作品详情 | 保留真实身份；重复引用在详情说明对应同一原始记录 |
| 评审与结果 | 等待评审 / 评审已完成 / 未达到题目要求 / 部分要求未满足 | 状态必须来自真实阶段；“未达到题目要求”保留具体未满足项，不换为“表现良好” |

| 数据与时间 | 分项测试结果 / 历史记录 / 测试时间 / 评分依据 / 统计范围 | “正确率”与“覆盖情况”分开，日期、时区、分母不可省略 |
| 评分说明 | 作品按逻辑答题、规则图形和场景要求的完成情况依次比较；上述成绩一致时，参考视觉呈现质量的评价。 | 保留真实排序顺序及主观评价边界，不合成无依据的 IQ 分 |
| 读取失败 | 暂时无法加载测试记录，请稍后重试。 | 服务端错误详情保留后台；重试仅重新读取，不调用模型 |

正式化意味着准确、自然且面向用户，不以生僻词、抽象名词堆叠或营销承诺制造专业感。完整审校范围包括导航、标题、摘要、筛选项、字段、单位、卡片、图例、Tooltip、加载/空态/错误、按钮、对话框、下载提示和无障碍标签；统一术语并进入两主题 i18n。后台的执行状态、取消影响、预算来源也使用完整明确语句，但不混入用户作品卡片。模拟标识在本地演示持续保留，不能为了观感把手绘图伪装成实测作品。

UI 验收至少覆盖桌面、平板、手机，明暗主题、站点现有个性化主题、200% 缩放及键盘焦点；使用长中文/英文别名、多行说明、×0/×1/小数/缺失倍率、1/2/3 张作品、全部空/失败/暂停状态。并排检查本站模型状态与测试页、原设置与测试设置的视觉连续性；验证无横向溢出、按钮可触达、排序后整行正确、退出弹层恢复焦点。对比截图与控件操作证据纳入 G5，不能以静态 HTML 通过代替真实组件验收。

本轮完成的是组件选择、字段与布局契约，没有新增 React UI、运行 shadcn CLI 或通过真实浏览器视觉验收。实现时先使用仓库已有组件，缺少时才按项目技能查阅和补充，不另引入组件库。本节将设计技能落到可执行清单，但不把设计规范说成已上线效果。

## 17. 新增边界验收与持续运行标准

以下在本地模拟上游、受控时钟和三数据库完成；不能在生产反复关闭真实渠道做破坏性验证。

1. 关闭/恢复发生在排队前、派发许可前后、流式生成中、评分中、发布后五个时点，旧配置结果不会回写当前优选；其他渠道和下一周期继续。
2. C1 同属 A/B/C，删除 A 订阅只移除 A，不中止 B/C 需要的任务；取消最后一个有效订阅才撤销未发任务。
3. 签名相同共享一次，模型映射、推理参数、请求头、Key 版本或上下文不同拆开；仅售价和布局不同仍可共享。
4. 同一轮相同任务由多个节点/组同时发现时，唯一键与条件领取只允许一份派发；成本全局一次，组内统计不因补位重复。
5. A→B、A→A+B、A+B→B、删除后同名重建、明确 rename、事件丢失、批量操作中 channels/abilities 短暂不一致逐一覆盖。
6. 新增成员自动接续但不越过模型范围/总预算；连续改组不会刷出无限补测。同轮晚加入只有参考标记，下一轮自然形成正式样本。
7. 视觉 judge/渲染分别停止两个周期，逻辑仍发布；恢复只补评已存内容，不重复生成、重复计费或篡改原历史发布版本。
8. 隐藏主操作原子停止并隐藏；hide_only 保留运行，show_only 不恢复运行。停止后重启、蓝绿切换、预算跨日均不自动恢复；并发隐藏/恢复通过 revision 拒绝旧操作。控制提交后仍在途请求准确显示 stopping/费用未知。
9. 两管理员同时排序出现 409 而非覆盖；手机上下移动、键盘操作、保存失败回退、恢复全站 GroupOrder 均有效；未知新组稳定追加。
10. 普通用户无法通过结果 ID、图片 URL、旧前端缓存发起新访问绕过隐藏策略；同一内部 run 的不同组投影不泄露其他私有组。
11. 所有通道同时失败时保留真实无结果状态并在下一轮继续尝试；无可用模型、无预算、存储受限时明确局部阻塞原因，不伪造结果或无限重试。
12. 获授权的真实小范围验收至少观察两个完整半小时周期；稳定性验收在本地/专用环境模拟至少 24 小时（48 槽）含随机拓扑变化、worker 重启和故障恢复，输出每组轮次覆盖与去重计费报告。
13. 全站停测 C1 后所有组停止新派发；仅 A 停测 C1 时 B 保留共享任务；最后一个订阅取消时才终止共享任务。停测/恢复不写业务 Status、权重、成员、原监控开关，普通请求仍按原路由处理。
14. 全局/组内/模型排除叠加后逐项恢复，准确显示剩余阻塞；移动、改名、业务重启、进程重启、手动执行均无法绕过人工排除。全组排除显示人为停测且不伪造三张作品。
15. 渠道同名、渠道改名、分组别名、正式路由改名、部分迁移、改名冲突、同名重建、直接 DB 修改无事件分别验证；历史/排除/顺序均按固定身份归属，无法确定时不猜测合并。
16. 用相同模拟 fixture 覆盖两前端功能；Default 在原主题/暗色/手机/键盘下与现有设置页和模型状态并排比较。主题切换不留下独立配色，排序或显示别名变化不重测；示例关闭按钮无真实网络副作用。
17. 只有一个渠道时：无历史只出一张实图，有两份合法近期作品时可呈三图且各自时间/题目正确；复制图同 hash 不冒充独立作品，跨版本/移出/私有历史不能被补入当前组。
18. 开启 K=3 后主测分数不被另两张高分替换；共享组不重复付费；补充样本预算不足时主测优先。三次生成同图时不无限重试，来源与样本数仍真实。
19. 15/30/60/120 预设与 20/37/45/90 分钟自定义、无效输入、容量不足、跨日窗口、每周运行日、夏令时重复/缺失时刻、同时改计划/停止、worker 重启与新旧计划交界逐一模拟；37 分钟跨午夜不重置，窗口外不发，超时不越封存，图表/方法/费用与真实计划一致。
20. 新增组/渠道/模型、批量编辑和事件丢失后，发现清单自动完整更新；每条关系可追溯适配节点与预算许可。未纳入项仍可见原因，既有人工排除不被自动继承覆盖。
21. 前台文案与配置联动；隐藏统计模块后不得继续显示依赖该模块且无来源的汇总，方法与实际题型/周期一致。样本正确率不能把缺失分母、补充样本或近期填图当作本轮通过数。

内部目标：常规业务关系变更 5 秒内影响投影/取消队列、事件丢失 60 秒内对账发现；普通 API 请求发送前强制校验。任务产生成功作品的延迟受模型、预算和资源影响，报告真实耗时与缺失，不将这些内部目标解释为外部服务无条件 SLA。

### 18.2 执行器的真实调用契约

1. 从本站现时 channels/abilities 及已批准范围解析目标，冻结 channel ID、Key slot、原始/映射模型、协议、profile、题目及配置版本。调用实际配置的上游地址，复用现有供应商 adaptor，不把所有渠道都硬接成 Chat Completions，不按模型名称猜接口可用性。
2. 为合成测试建立明确 purpose，独立预算、日志和统计；完整走必要映射、参数覆盖、静态头、代理与并发限流。现有 IsChannelTest 会跳过客户端透传，不能靠简单切成 false 引入普通用户扣费等副作用。先对所选 profile 比较测试路径与普通业务路径的有效请求差异；所需客户端上下文无法合法复现则标“暂不可测”，不得伪造 CLI 身份或借用用户会话。
3. 子请求从调度任务 context 派生 deadline/cancel，不能继续用独立 Background 隔断停止指令。超时按协议/profile 验收后确定，默认 180 秒不等于所有推理模型都能完成；预估无法适配本轮窗口的配置在启用前提示调整范围或受控超时。
4. 在 adaptor 响应处理旁建立有界收集器，统一提取可见输出与 usage；不复用 8 KiB 日志截取，也不把 SSE 每行分别当作完整 JSON 回答。覆盖 SSE 跨网络包、多行/心跳、分块 UTF-8、Responses/Claude/Gemini 的完成/错误语义和末尾 usage。设置总接收上限、可见文本上限和取消机制，超限标截断；不能先无限缓存再截取。
5. 只有对应协议的完整终止条件、无终止错误且可见回答满足格式时进入判分；空回答、拒答、工具调用而无最终文本、断流、超时、超限各有明确原因。工具不实际执行，测试题不提供工具能力；不会从隐藏 reasoning 文本搜索标准答案。
6. 模型原始题目、可见回答、结构评分、PNG 与 judge 证据按同一个 run 可追溯。场景 judge 使用独立已校准档位；被测渠道不自评，模糊判断保留 uncertain。若渲染/判分失败，保存回答并记对应阶段失败，不能当作模型智力下降。
7. 发出每一次调用前记录 attempt 与预算许可；上游 request ID 有则保留，无则明确缺失。usage_source 至少区分 provider / locally_estimated / missing，cost_source 区分配置价估算 / 已核对账单；上游 usage 也不等于已出账金额。传输失败不按“没收到文本”一概判定可免费重试：读超时/断连/可能已接收均按未知发送处理，除非可证明未发送或上游支持验证过的幂等。
8. 发送前和发布前再次验证停止策略与当前订阅。结果发布只引用真实存储制品；复制三格引用相同 run，不生成三条测试证据。新周期、配置变更、渠道关闭、隐藏默认停测均必须通过持久化状态驱动。

以上 1–8 条同时受第 4.1 的目标上下文和同轮凭据锁定约束；旧渠道测试方法只是重构起点，不是可直接交付的执行器。

### 18.3 先交付最小真实闭环，再铺开所有 UI 与渠道

| 门槛 | 在哪里、做什么 | 可检查的交付与通过条件 |
| --- | --- | --- |

| G2：拓扑与控制 | 同一代码，本地模拟时钟、SQL/Redis、多 worker 和三数据库 | 关闭/共享/移组/改名、局部排除、整行排序持久化、默认隐藏停测、日志鉴权与恢复符合第 17 节 |

| G4：持续实测 | 经授权在部署位置运行至少两个完整有效测试周期 | 先小范围证明持续运行，再按批准范围核对每个应测目标；固定轮次、覆盖缺口、去重费用、前三来源和生成时间可核对；默认30分钟，其他配置按实际周期；本机可达不替代部署位置可达 |

G1 不是临时 curl 成功截图：必须运行准备发布的同一执行器与存储/判分路径。先实现它所需最小管理详情和用户结果组件，成功后再扩展题库、规模与视觉细节；不能先做满 UI 然后把核心链路留成占位。G2 与 G3 中故障注入均在本地/专用环境，不能为了验收关闭生产业务渠道。生产只接收本地验证产物、运行获授权的轻量验收；不编译、不装依赖。

每份验收报告记录：代码 commit、制品哈希、时间/环境、测试范围、suite/profile/judge 版本、用量上限和实际账本、round/run/attempt ID、预期与实际、脱敏证据路径、失败原因及未覆盖项。敏感配置不纳入报告。可控基准题与 SVG 必须得到预期判分；真实模型答错不阻止管线验收，但会真实呈现低分，不能以“所有真实模型答对”作为可用标准。

真实探测仍需要明确的目标与费用上限；当前尚未给出这些配置，也没有实现新版执行器，因此本轮不会调用真实模型或把模拟结果当作实测。下一项工程交付应是 G0/G1 所需的最小闭环及其证据，后续美化不应阻塞这条主线。

### 18.4 全目标覆盖与设置兑现的验收样例（V6）

**本地可控上游证明。** 建立 A、B 两个分组，C1 同时属于 A/B，C2 只属于 A，C3 只属于 B；每个模拟上游返回可识别的 fixture 标记并记录实际请求。A 同时有四个应测渠道时，断言四个都收到完整试卷，用户仅选三份展示。不同模型能力矩阵只生成合法 channel/model 组合，不做无依据的全笛卡尔积。

- C1 在两组的有效条件相同：每题一次物理调用、两个合法投影、一次费用；修改 B 的有效推理档位/请求覆盖后应拆为两份目标，fixture 收到不同的正确参数。
- C2 超时不能转给 C1 并把成功写到 C2；后台保存 C2 的失败/未知状态。C3 停测时调用数为零，其普通业务状态不变；其他目标及下一轮继续。
- 多 Key 策略可轮换，但一套三题接收到的匿名凭据槽一致；指定槽失效不偷偷换槽补齐。测试执行账号的原分组不同于 A/B 时，fixture 仍收到 A/B 各自要求的有效参数。
- 模型映射、代理和静态头覆盖有预期值断言，脱敏记录与实际发送对应；禁用、移组、删后同名重建与发送/发布阶段变更不会把作品归给错误对象。沿用第17节故障场景，不在生产切断业务验证。

**真实范围证明。** 在获授权预算内生成覆盖报告，主键包括 `group_uid + requested_model + profile + channel_id + execution_revision`。等价跨组记录引用同一实际 run，并附各组关系/有效请求等价证据。每行列目标发现状态、批准状态、实际发送/完整回答/判分/发布状态、最近时间、round/run/attempt、配置版本及阻塞原因；主测/补充、自动/手动分开。不能只记一个组的最近成功时间代替组内每个成员。

通过条件为批准清单中的每个独立目标都有当前版本的真实完整回答和预期判分/制品证据，各组投影合法；失败或暂不可测对象保留缺口，系统可在注明覆盖范围的前提下继续运行，但不能宣称全量已测通。逻辑答错/画错只影响成绩，不影响“真实调用链已验证”的结论；渲染或评审未完成则对应阶段仍未通过。对初始上线未批准的对象显示未纳入原因，不偷换成已覆盖。新增/修改目标沿相同路径接续验收，最近证据超过有效周期不能继续标当前已验证。

全量目标与预算/周期冲突时，启用预检显示所需调用量、预估费用与预计完成时间，由管理员在现有范围/预算/计划控件调整；不能悄悄只测最好的三个，也不保证上游故障时一定成功。局部阻塞不停止其他目标，下一有效轮按预算继续，重试仍遵守已发送未知的成本边界。

**后台到用户端证明。** 用 A 的业务名称、已配置倍率和说明建立基线：设置测试别名与自定义说明并发布，确认正式页改变；刷新/重启后保留；业务路由 key、GroupRatio、abilities 和令牌均未被修改。再改业务倍率，确认别名保留、倍率跟随；恢复名称/说明继承后再改源，前端自动跟随。覆盖 ×0、缺倍率、访问者不同说明、同名别名、隐藏组和正式改名承接。其余字段逐一执行14.11矩阵，不能仅挑两个控件演示就声称后台全部有效。

交付物为脱敏的目标覆盖报告、逐字段控制验收报告、真实调用与制品索引、UI状态截图及尚未通过项。当前这些报告尚未生成；本节规定完成标准，不是执行结果。

## 19. 完成定义

一次配置范围、费用、计划和评审模型后，本站能自动发现现有/新增组与渠道模型、按规则接续、合并跨组等价任务、按有效周期生成可复查试卷、锁定渠道执行、分项判分、保存证据并更新作品优先的分组页面。关闭/增删/改组不要求手工维护映射；不依赖外部测试网站在线或每轮人工挑图。

管理员在现有运维设置中能独立停止/恢复全站或单渠道测试、仅在某组停测、隐藏/显示、调整三层顺序、管理范围/题型/费用并查看原因。停测不关闭业务渠道，改显示名称不丢历史、排除或排序；正式路由改名可审计承接。用户页与后台都沿用本站已有 UI 与组件。局部故障不扩散，自动阻塞可恢复，人工停止不自动解除；历史、当前归属、样本去重和实际费用均可追溯。

用户导航按使用日志 → 智商测试 → 模型状态落位；隐藏主操作默认停全部测试，明确的仅隐藏选项可保留运行。管理员在运行记录中查看实际调用与判分证据，排序移动整行且持久化。完整链路的真实验收先于视觉效果上的完成声明。

三图来自可核对的本轮/近期/补充作品，样本不足不伪造；用户文案突出真实服务价值，方法说明与实际设置一致。全部前台模块有对应后台控制，明暗主题下列表/详情/管理状态完整；间隔与时段可调且保留历史计划，自动同步不绕过权限、成本和人工停测。

V6 进一步要求：全部应测目标都有逐项覆盖证据或明确缺口，不能将前三展示等同全量测试；每个后台设置都有持久化、消费者与端到端生效证据。分组默认继承本站名称、授权描述、图标、顺序和售价倍率；测试页别名/说明独立覆盖且可恢复继承，倍率始终来自真实配置。最终 UI 按15.9在现有正式组件中实现并验收。

没有真实价格、未选 judge、未完成校准或 G1/G3/G4 真实验收时，应明确标记对应未完成项，不能仅凭静态演示、mock 通过或单次 HTTP 200 称整条链路可用。本文是实施方案，不是已完成上述测试的报告，也不构成生产写操作或持续付费授权。

## 20. 不公开的真实验收与动画模板补充

目标是同一正式组件、同一业务执行器、真实分组/渠道/模型、真实上游回答与可核对记录，验收访问仅对指定管理员开放。它不是当前的内存模拟预览，也不能保证不同网络/负载/随机生成条件下每次回答完全相同。

建议实施边界（未部署）：

1. 同一版本制品运行在独立验收实例；不切换正式入口，不把验收实例接入用户流量。使用独立数据库、Redis 命名空间或实例、队列、日志及作品目录，避免修改线上运行开关、预算或结果。
2. 只同步必要的真实分组、渠道归属、模型映射与倍率配置；不用整库客户资料来演示。密钥只供获准执行器使用，不进入前端、源码和交付文档。验收环境的配置副本应标同步时间；若需持续跟随生产，增加只读同步，不能把一次导入称实时自动同步。
3. 现有蓝绿候选 `NODE_TYPE=slave` 不运行智商测试 worker。真实验收需独立任务进程；不得把连着生产库的候选临时切成 master 以启用任务。现有只允许校准后自动运行的门禁，需增加隔离、限次、限额、仅后台可见的验收/校准流程；不得伪造校准报告来打开生产门禁。
4. 先选明确获准的少量分组/模型/渠道做有限轮真实调用，再覆盖共享、关闭、停测、移组及后台保存读回。真实上游调用仍消耗渠道额度；范围、次数、预算和运行位置在执行前明确。普通用户无法通过页面、API 或制品直链访问验收结果。
5. 验收通过后固定同一源码/构建版本，形成可审查制品及差异；用户确认后再依原有蓝绿流程发布。验收与生产的数据库、运行配置和网络条件差异必须列明，不能把“同版代码”说成环境绝对一致。

绘图题库按用户原模板输出 HTML 内嵌 SVG 2D 动画，固定鹈鹕题保留原提示词；随机题冻结主体、动作与场景，同轮使用同题，保留实际发送的全文与题目版本。固定鹈鹕题不沿用旧试卷额外添加的海边、围巾、橙子等六项评分要求；随机试题只能依据实际提示中明确给出的要求评定。

resvg静态渲染器不能承接HTML/CSS/动画。动画使用单独浏览器隔离分支：无业务凭据、无外网、资源与执行时长受限；保留原始回答，以固定画布和统一时间点生成动画播放制品与评审帧。本站页面播放受控制品，不在主页面直接执行模型返回的HTML。是否在动、主体与自行车的动作关系以及跨帧连续性必须有时序证据，单张漂亮图片不能判定动画达标。新套题版本和人工校准完成前，静态套题成绩不得作为动画成绩混排。

本地首版观察参数为600×400、100毫秒间隔、48帧（0至4700毫秒），生成无损APNG和0/900/1900/2800/3800/4700毫秒的六帧证据。点击后播放，停止恢复首帧；深浅主题只改变控件，不改作品像素。评审请求与恢复复用均以真实拼图哈希核对；原题全文与回答保留。采样未观察到变化时不判运动通过，观察到变化也不自动证明骑行动作。题库、渲染器和浏览器版本进入校准门禁。以上链路已完成本地模拟验证，随机完整题库、Linux隔离部署、人工校准和真实私有验收继续按实施记录验收。

## 21. 新参考图的信息密度与详情补充

沿用用户认可的三图在上、历史在下。借鉴新参考图的紧凑信息组织，不将竞品的左右分栏、可用性统计和未经验证的断言带入本站。分组名/模型/倍率集中，说明自然换行；正文约13px、辅助信息约12px，保持对比度、32px历史点击区与明显键盘焦点。手机三图单列、时间线共用横向滚动，不把整个页面撑宽。

每个历史色块指向该轮该题型的原始样本，详情默认打开所点题型，使用原生选项卡切换同样本其它题目。详情依次呈现题目级判定、作品、完整原题、真实生成数据、逐项依据和原始回答；长题目/代码在区域内滚动，不挤压其它内容。不得把一条题目的达标状态扩展成该模型整体“不降智”结论。

生成数据仅来自该样本的实际生成调用，评审和渲染不计入生成耗时。时间只按可信的起止记录显示；未知终态不以进程恢复时间冒充上游完成时间。Token数采用明确的上游报告值，保留真实0；不存在、格式不合法、分段累积不能确定口径或估算值，显示“—”。首字延迟、推理强度等未采集字段不因竞品有展示而伪造。后台可查完整调用证据，用户详情只提供允许公开的数据和匿名记录身份。

首页底部增加三栏专业方法摘要，完整内容仍保留在六章节阅读面板。摘要标题复用文案管理中的“对象与评分”“精选与来源”“结果的含义”，按钮进入对应章节；show_method同时隐藏摘要与所有阅读入口。分组展示与真实分数、来源、时间的控制边界不变，文案编辑不得改写事实。

Default复用Card、Sheet、Tabs、Tooltip，Classic使用对应Semi组件；使用各主题现有字体、色彩变量和设置机制。验收包含深浅色、手机、键盘、历史格到原题/判定的对应、方法摘要到章节的对应，以及隐藏状态下无残留入口。当前实现状态以独立实施核验记录为准，不据UI完成推定动画、真实渠道或整个V6已验收。
