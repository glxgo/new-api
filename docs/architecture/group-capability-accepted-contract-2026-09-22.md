# 飓星 API 智商测试：用户已确认要求与验收基准

用途：防止上下文压缩、临时演示或实现便利改变已经确认的产品方向。继续开发、交接或恢复上下文时，先读本文件，再读完整 V6 与实施核验记录。本文是需求基准，不是完成声明；未完成项必须在实施核验记录中明列，不能降低验收条件来消除差距。

## 2026-09-23 正式确认（优先于下方历史内容）

- 优化信息阅读与图片查看须保留原始测试结果：不重绘、删改图中文字或修正模型答案后冒充原作；题目、标准答案、来源提取数字与来源判定分别呈现。核对作品差异先确认记录时间和来源快照，不把旧快照误当成源站最新表现。
- 作品卡片只展示原图，题目、答案判定、时间及记录数据点击后查看。图片铺满卡片宽度，框高跟随原图比例，不裁切、不拉伸、不溢出；横竖图允许不同高度。原作品内部文字保留，不改写模型输出；下方历史继续保留。
- 用户明确确认当前正确答案为21；各条历史记录按当时保存的答案与判定展示，不追溯覆盖模型原答。完整当前实施规则以 `pelican-archive-integration-plan-2026-09-22.md` 为准，下方 V6 只作历史背景。
- 用户接受外部网站为唯一测试源，明确不再要求 HTML/SVG 2D 动画版本；以外部当前真实测试为准，授权面向正式用户功能的本地开发与验证。
- 同一渠道在多个本站分组引用同一份结果。外部 provider_id 与本站 Channel.Id 显式关联，名称不能作为身份；分组只决定展示，不调度测试。
- 旧执行器停止接入生产启动、路由与前端入口；保留历史源码，不删除用户已有成果。
- 当前源站无全局轮次，以每个渠道/模型的完整记录原子替换，等待期间继续保留上一条；不会把不同时间记录称为同一轮。
- 继续保持三图上、历史下、真实不足不复制、new-api 原生组件、深浅色和紧凑信息层级。控件语义改为同步、映射、展示、文案，不能声称控制外部测试。
- 正式上线仍待用户单独确认，生产只读；沿原蓝绿流程发布。

## 2026-09-22 历史标准：停止旧开发，改为外部鹈鹕存档接入

本节优先于下方全部旧 V6 要求。用户明确停止当前进度，新的责任划分为：外部鹈鹕网站已经接入飓星 API 的渠道，由外部网站完成各渠道测试并保存结果；网站已迁移服务器；飓星 API 读取已有存档并在本站展示。用户访问展示页不发起鹈鹕测试，本站不继续开发自己的出题、模型调用、评审与随机题库链路。旧源码保留，当前没有授权删除或立即重写整个功能。

- 截图明确指向已有测试存档，不等于复制整套测试服务源码到中转站。内网穿透只是待核实的连接建议，尚未选择或搭建具体方案。
- 文件格式、索引、完整性/版本标记、渠道/模型身份、测试时间、已有成绩与原题是否保存，须以只读检查结果为准。不能把旧 V6 的三题型、分数、Token 或历史字段强加给外部文件。
- 外部网站已经负责把飓星 API 的渠道接入测试；本站不再重新按本站分组调度，也不把本站分组映射当作测试执行前提。展示时以外部存档中的渠道/分组/模型字段为事实来源；若存档没有分组字段，就只展示渠道结果，不凭名称猜造分组。
- 外部渠道的稳定身份必须使用存档中的不可变 `source_channel_id` 或等价字段；本站显示名称只能作为展示字段。名称变化不能改变历史归属，无法获得稳定身份的记录进入“待核对”而不是自动合并。
- 暂停同步、隐藏展示是本站职责；外部停测和测试周期属于外部系统。仅有读文件能力时不能声称本站开关可以控制外部测试或费用。
- 现有 new-api 风格、深浅色适配及用户认可的布局可作为后续展示基础；具体前后端逻辑与控件须先按实际存档重新设计，当前不继续旧方案实现。
- “迁移只改地址”的前提是读取协议、路径与文件结构保持兼容；此前尚无核验。生产部署仍需用户确认并沿现网蓝绿规范，当前无服务器操作。

## 以下为旧 V6 历史要求（冲突项已被上述新标准替代）

### 2026-09-22 最新补充：信息密度与详情

- 参考用户新发六图优化信息密度，合理缩小辅助文字、收紧模块留白，继续保留已认可的三图在上、历史在下；不照搬竞品的左右分栏来替换认可布局。
- 分组名、模型、倍率与说明清晰集中；历史各题型同轮对齐。正文以可读为前提缩至约13px、辅助文字约12px，键盘焦点和点击区域不随字体一起缩小。
- 点击某个历史色块优先打开对应题型，原题、逐项评定、原回答、生成数据和记录身份按层级查阅；其它题型通过原生选项卡切换，避免连续堆叠成长页。
- 页面底部保留方法摘要，完整体系解释继续使用六章节阅读面板；摘要标题沿用后台对应文案，方法隐藏开关同时控制摘要和阅读入口。
- 可借鉴信息组织，不复制“同 Codex CLI”“答错即降智”或未采集的首字时间、推理强度。生成耗时不包含渲染/评审，未知终态不以恢复时间伪造完成耗时；Token 只采用可信上游报告值。正文、色块和作品必须对应真实记录。

### 2026-09-22 最新补充：动画试题与不公开的真实验收

用户给定鹈鹕测试的原始提示词，必须作为试题保存，不得擅自改成静态 SVG：

> 生成 html，内容是 svg 绘制鹈鹕骑自行车 2D 动画，不进行测试，不使用 skill，不参考本地文件。

- 随机图像类题目依照同一输出模板，替换场景/主体/动作等试题内容；逻辑题仍单独管理。提示词中的“不进行测试、不使用 skill、不参考本地文件”是对被测模型生成作品时的要求，不是上线授权或调用付费上游的授权。
- HTML/SVG 动画是最新绘图目标，优先于旧方案及当前静态 SVG 实现。当前 resvg/PNG 只能支撑静态图，不得宣称已完成该动画链路；需要补齐隔离动画渲染、播放制品和多帧/时序评定，重新确定题库版本及校准。
- 用户希望同一真实产品代码、本站真实分组/渠道/模型、真实调用，但暂不面向普通用户开放。独立验收环境是建议实施方式，尚未创建、上传或发起真实调用；启用真实渠道费用和共享服务器写入仍待具体范围及授权。
- “自动接入本站分组”是从运行环境的真实业务配置派生，不需人工再绑定。独立验收环境使用配置副本时，不等于已自动跟随生产，持续跟随还须只读同步机制。
- 保留 P2 布局、整轮替换、文案管理、控制与权限要求；动画改造不能退回独立演示页替代正式组件。

| 文案管理收缩 | 后台文案管理按概览、作品、方法分区折叠，支持展开/收起，保留未保存内容与修改提示 | 直接复用 new-api 原有设置折叠组件及保存/预览机制；折叠不触发保存或丢弃 |

## 不能在压缩后变成“已完成”或“已确认”的事项

- 三图不足时，V6 建议以近期真实作品补位，或明确引用同一作品；不能虚构第三个独立渠道或换图冒充实测。不能把当前实现仅展示 1–3 张作为已完成原三图策略。
- 费用范围、真实模型验证和人工视觉校准仍需要真实输入与授权。模拟回答只能验证链路，不能证明真实模型达标或全部渠道已测通。
- V6 题库数量、持久化恢复、保留策略、容量控制、双主题及完整后台矩阵等仍按完整方案验收，不能因为局部构建或测试通过而删掉。
- P2 是明确认可的布局；P1 是开发过程中的布局偏差。截图中的模拟作品只能用于交互验收，生产制品必须来自真实测试记录。
- 最新用户消息通常是在补充当前开发任务。不要因为用户提醒布局、权限或上下文保持，就丢失原 V6 开发任务；也不要未经确认擅自开始生产操作。
