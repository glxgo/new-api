# 多入口计费与虚拟会员产品需求规划

## 1. 文档信息

- 文档状态：规划完成，待业务口径确认后进入技术实现
- 规划范围：多请求入口、入口计费倍率、浏览器测速、虚拟会员商品、双周期额度、自动成团档位、用户看板、独立管理后台
- 不包含：DNS/Nginx 实际改动、生产配置、代码实现、支付上线和历史数据迁移
- 时间口径：后台与用户页统一显示北京时间（Asia/Shanghai），接口保存 Unix 时间戳
- 视觉参考：用户提供的额度卡片与购买卡片仅作为信息层级参考，沿用现有站点设计系统，不复制账号文件名、邮箱或“真实 GPT 账号”暗示

## 2. 产品目标

### 2.1 多入口

1. 同一把 API Key 可以选择不同公网入口，不需要重新创建 Key。
2. “三网优化 URL”经线路机转发到落地机，保持当前原价计费。
3. “海外直链 URL”由用户直连落地机，并在原有请求扣费结果上应用后台配置的入口计费倍率。
4. API Key 页面同时展示两个入口、计费倍率、复制操作和当前浏览器网络的测速结果。
5. 入口选择只影响网络路径和最终扣费，不改变模型、渠道、API Key 分组、订阅归属或上游路由规则。

### 2.2 虚拟会员

1. 增加独立的“虚拟会员”商品与权益体系，支持 GPT Plus、Pro 5x、Pro 20x 以及以后新增的自定义方案。
2. 虚拟会员不是官方 GPT 账号或官方会员，而是站内 API 额度权益；用户页和购买确认页必须持续明确说明这一点。
3. 每份虚拟会员实例具有周额度，以及可按方案开启的 5 小时额度；启用 5 小时额度时，一次请求同时消耗周额度和 5 小时额度。
4. 管理员可以手动执行“全站虚拟会员周额度重置”，立即开启新周周期，并把下次重置时间设为本次重置的 7 天后。
5. 支持单独购买、2 人团、3 人团、4 人团。拼团不等待其他用户，付款成功即自动成团；人数只决定购买价格和每份实例获得的均分额度。

## 3. 核心术语

### 3.1 API 入口

用户调用 API 时使用的公网 Base URL。入口决定网络路径和入口计费倍率，不等于上游渠道，也不等于 API Key 分组。

### 3.2 三网优化入口

网络路径为“用户 → 线路机 → 落地机”。首期默认计费倍率为 `×1.00`。

### 3.3 海外直链入口

网络路径为“用户 → 落地机”。后台可配置入口计费倍率，例如 `×0.95` 表示按原扣费结果的 95% 计费，即九五折。

### 3.4 入口计费倍率

应用在现有请求最终应扣额度上的固定倍率。它不是“分组倍率”、不是“渠道成本倍率”，也不改变充值金额或商品售价。

### 3.5 浏览器线路测速

从用户当前打开网站的浏览器分别访问两个入口的轻量探针，测量 HTTPS 往返时间。它反映当前浏览器所在网络，不代表其他设备、服务器、CLI 或真实模型生成速度。

### 3.6 虚拟会员方案

管理员维护的商品模板，包含名称、说明、有效期、适用模型/分组、周总额度、可选 5 小时总额度、单买与 2/3/4 人团价格。

### 3.7 虚拟会员实例

用户完成购买后实际持有的一份站内权益。实例冻结购买时的价格、额度、有效期、人数档位和适用范围，不被后续方案编辑静默改写。

### 3.8 自动成团档位

单买之外的 2/3/4 人团购买方式。不存在成员、邀请、等待、团长、成团截止时间或失败退款流程；支付成功后系统直接签发一份均分额度实例。

## 4. 多入口用户需求

### 4.1 API Key 页面

把现有单行“API Base URL”替换为“API 入口”卡片，桌面端和移动端均包含：

| 字段 | 三网优化 URL | 海外直链 URL |
|---|---|---|
| 名称 | 三网优化 URL | 海外直链 URL |
| 地址 | 后台配置的公网 Base URL | 后台配置的公网 Base URL |
| 计费 | 原价 / `×1.00` | `×后台倍率`，例如 `×0.95` |
| 路径说明 | 线路机转发，适合中国大陆网络 | 直连落地机，适合海外或优质国际网络 |
| 操作 | 复制 | 复制 |
| 测速结果 | 中位延迟、状态 | 中位延迟、状态 |

交互规则：

1. “开始测速”一次并行测试两个入口，按钮进入 loading 且禁止重复点击。
2. 每个入口显示“测试中 / xx ms / 超时 / 不可达”。
3. 测试完成后给出“当前浏览器网络下建议优先使用”提示，但不自动改写任何客户端配置。
4. 结果必须附带“仅代表当前浏览器到入口的网络延迟，不代表模型响应时间”。
5. 单入口失败不影响另一个入口完成测试；支持单独重试。
6. 复制成功、失败和测速失败均使用可读文本反馈，不能只用颜色表达。

### 4.2 后台入口配置

增加“API 入口”配置页，管理员可以维护：

- 对外显示名称；
- 入口标识；
- 公网 Base URL；
- 网络路径说明；
- 计费倍率；
- 是否启用；
- 是否在 API Key 页展示；
- 排序；
- 测速探针是否可用。

首期业务约束：

- 必须且只能有一个默认原价入口；
- 三网优化入口默认 `×1.00`；
- 海外直链入口的折扣输入范围建议为 `0.01–1.00`；
- 后台输入 `0.95`，前台显示 `×0.95` 和“按原价 95% 计费”；
- 修改倍率只影响修改生效后的新请求，不追溯历史日志或历史消费。

### 4.3 计费范围

入口倍率应用于：

- 普通同步 API 请求；
- 流式请求；
- Responses、Chat、Claude、Gemini 兼容请求；
- 异步任务和任务完成后的差额结算；
- 钱包、普通订阅和虚拟会员实际消耗。

入口倍率不应用于：

- 钱包充值金额；
- 订阅套餐或虚拟会员购买价格；
- 邀请返利、分红、提现；
- 管理员加额、兑换码和赠金发放；
- 明确独立于正常 API 用量的处罚费用。

## 5. 虚拟会员商品规则

### 5.1 方案字段

每个方案至少配置：

- 方案名称与稳定编码；
- 副标题、适合人群、详细说明；
- 有效期；
- 周总额度；
- 是否启用 5 小时额度；
- 5 小时总额度；
- 适用 API Key 分组；
- 适用模型范围；
- 单独购买价格与开关；
- 2 人团价格与开关；
- 3 人团价格与开关；
- 4 人团价格与开关；
- 推荐标记、排序和上架状态；
- 每用户最大购买次数；
- 是否允许钱包本金支付及支持的外部支付方式。

管理员填写的是方案完整额度。购买 `N` 人团时，系统按以下公式计算单个用户实例权益：

```text
实例周额度 = floor(方案周总额度 / N)
实例 5 小时额度 = floor(方案 5 小时总额度 / N)
```

`N=1` 表示单独购买。整除余数不再分配，防止多个虚拟份额合计超过管理员设置的总额度。后台和购买确认页必须预览计算结果。

### 5.2 用户购买页

左侧侧边栏在“订阅套餐”上方增加“虚拟会员”。页面结构：

1. 顶部独立公告，由管理员编辑；
2. “这是站内 API 额度权益，不是官方 GPT Plus/Pro 账号”的固定风险说明；
3. 方案卡片网格；
4. 我的虚拟会员；
5. 购买记录与规则说明。

方案卡片沿用参考图的信息层级，但修改为：

- 标题、推荐标识、价格、方案完整周额度、有效期；
- “额度档位”区域只展示单买、2 人团、3 人团、4 人团的价格和可得额度；
- 删除“自动升级”“升级”“最高”等真实成团阶梯文案；
- 底部固定说明改为“自动成团：无需等待其他用户，付款后立即获得对应均分额度”；
- 底部保留两个按钮：“单独购买”“发起拼团”；
- 点击“发起拼团”后，在弹窗或移动端底部抽屉选择 2/3/4 人团，并实时显示支付金额、周额度、可选 5 小时额度和有效期；
- 提交支付前再次展示权益快照并要求确认。

### 5.3 我的虚拟会员

每张实例卡展示：

- 方案名、实例编号和购买档位；
- 生效时间、到期时间和剩余天数；
- 周额度已用比例、剩余额度、上次重置和下次重置时间；
- 方案启用 5 小时时，展示 5 小时额度已用比例、剩余额度和下次重置时间；
- 方案未启用 5 小时时，完全隐藏该行，不显示 0 或“未开启”占位条；
- 已绑定 API Key 数量与管理入口；
- 刷新额度按钮。

不得展示虚构的 GPT 邮箱、认证文件名、官方账号到期时间或“主动重置次数”，避免让用户误认为获得了真实官方账号。

### 5.4 周额度重置

1. 周额度采用全站虚拟会员统一周期。
2. 管理员点击“立即重置全部周额度”后，所有仍在有效期内的虚拟会员进入新周周期。
3. 新周期周已用额度为 0；本次重置时间为当前时间；下次重置时间为当前时间加 7 天。
4. 重置不改变会员有效期、累计历史用量、订单、5 小时窗口或 API Key 绑定。
5. 操作前显示受影响实例数和预计下次重置时间，要求二次确认并填写原因。
6. 每次重置生成独立审计事件；重复提交同一操作不得开启两个新周期。
7. 若以后需要自动周重置，应基于同一重置事件机制增加定时触发，不另建第二套逻辑。

### 5.5 5 小时额度

推荐首期规则：

1. 5 小时额度按虚拟会员实例独立计算。
2. 实例第一次产生成功消费时开启一个 5 小时窗口，避免用户未使用时白白损失窗口时间。
3. 窗口到期后的下一次请求自动开启新窗口，并把 5 小时已用额度归零。
4. 一个请求在周额度和 5 小时额度中记录同一份实际扣费；这不是扣两次钱，而是同时受两个上限约束。
5. 任一启用的额度不足以完成预扣时，请求拒绝，不跨实例拆分。
6. 管理员全站周重置不重置 5 小时窗口；若需要人工处理 5 小时异常，提供单实例管理操作，不与全站周重置混用。

### 5.6 API Key 使用方式

推荐首期采用显式绑定：

1. 用户购买虚拟会员后，为一个或多个兼容 API Key 选择具体虚拟会员实例。
2. 一把 API Key 同一时刻只能有一个正式资金来源实例，普通订阅与虚拟会员不能并列正式归属。
3. 现有 API Key 和普通订阅行为保持不变，不自动迁移，也不自动改扣新购买的虚拟会员。
4. 虚拟会员失效、周额度耗尽或 5 小时额度耗尽时，首期默认停止请求；是否允许钱包兜底由后续单独确认，不能静默发生。
5. 绑定前后变化进入现有 API Key 归属历史，并在用户确认框中展示。

## 6. 虚拟会员后台

独立“虚拟会员管理”页面包含：

1. 方案管理：新增、编辑、复制、上下架、排序、预览；
2. 档位管理：单买及 2/3/4 人团价格、开关、系统计算额度预览；
3. 公告管理：独立 Markdown 内容、启用开关和预览；
4. 实例管理：按用户、方案、状态、到期时间筛选，查看权益快照和绑定 Key；
5. 重置中心：全站周重置预览、确认、执行状态与历史；
6. 审计：方案变更、价格变更、手动重置、实例作废和人工调整；
7. 数据概览：有效实例数、各方案实例数、周额度总发放/已用、5 小时额度启用实例数和支付收入。

方案编辑规则：

- 编辑只影响以后创建的订单和实例；
- 已生成的有效待支付订单使用下单快照；
- 已购买实例使用购买快照；
- 如需调整存量实例，必须走独立批量迁移工具并再次确认，不能靠编辑方案追溯生效。

## 7. 导航与权限

### 7.1 用户侧

- “虚拟会员”位于“订阅套餐”上方；
- 支持站点现有侧栏模块开关；
- Default 与 Classic 两套前端保持功能一致；
- 移动端使用现有抽屉/菜单模式，不增加超过可读宽度的横向表格。

### 7.2 管理侧

- “虚拟会员管理”位于“订阅管理”附近，使用独立模块权限；
- 方案编辑可由管理员执行；
- 全站周重置建议仅超级管理员执行；
- 所有高影响操作必须记录操作者、时间、原因、配置版本和结果。

## 8. 非目标

- 不创建或交付真实 GPT Plus、Pro 账号；
- 不同步 OpenAI 官方账号状态或自动读取官方重置时间；
- 不做真实多人拼团、邀请链接、团长奖励、等待成团和失败退款；
- 不根据测速结果自动改写用户本地客户端；
- 不让客户端请求头自行决定计费入口；
- 不把入口折扣实现成新的 API Key 分组或渠道成本倍率；
- 不追溯修改历史请求、历史订单或现有普通订阅。

## 9. 待业务确认项与推荐答案

1. 虚拟会员是否只允许绑定后使用？推荐“是”，防止它与普通订阅/钱包的自动选择顺序产生隐性扣费。
2. 周额度是否所有适用 GPT/Codex 模型共享一个池？推荐“是”，由后台配置适用模型，不做每模型独立池。
3. 5 小时窗口从何时开始？推荐“首次成功消费时开始”，窗口到期后由下一次消费懒重置。
4. 全站周重置是否同时重置 5 小时额度？推荐“否”，两个周期独立。
5. 虚拟会员购买是否参与邀请返佣/代理分红？推荐首期“否”，待单独确认财务比例后再开启，避免默认继承产生意外支出。
6. 海外直链倍率是否允许大于 1？推荐首期只允许 `0.01–1.00`，因为当前需求是折扣入口。

## 10. 产品验收标准

1. 同一 API Key 使用两个入口时模型和上游能力一致，扣费差异严格符合入口倍率。
2. API Key 页能复制两个 URL，并能从当前浏览器独立测试两条路径。
3. 后台修改倍率后，只影响新请求；日志能解释原始扣费、入口倍率和最终扣费。
4. 单买与 2/3/4 人团均按后台价格支付，并按人数准确向下均分周/5 小时额度。
5. 购买页面无真实成团等待流程，文案明确“自动成团”。
6. 5 小时开关关闭时，用户端不展示也不执行该限制；开启时必须同时通过周额度和 5 小时额度校验。
7. 全站周重置幂等，重置后所有有效实例立即看到周已用为 0，下次重置时间为本次加 7 天。
8. 退款、失败请求和实际用量差额能同时正确调整周额度、5 小时额度和财务流水。
9. 旧 API Key、钱包和普通订阅在功能开关关闭时行为完全不变。
10. 页面在 375、768、1024、1440 宽度及明暗主题下可用，交互控件至少 44px，键盘焦点和错误提示清晰。
