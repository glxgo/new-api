# 幸运大转盘产品需求文档

## 1. 文档信息

- 产品名称：幸运大转盘
- 文档状态：核心规则已确认，进入开发设计
- 首期范围：用户端活动页、套餐卡赠送、充值进度、奖品发放、订阅消耗顺序、管理员配置与审计
- 活动期限：长期有效，不设预定结束时间，直到运营主动暂停
- 时间口径：北京时间（Asia/Shanghai）
- 视觉参考：现有参考图只提供布局和氛围参考，不继承其中的名称、固定奖励、消耗进度或奖品数量
- 公开文案草案：`docs/product/lucky-wheel-public-rules-draft.md`

## 2. 背景与目标

幸运大转盘通过“真实充值”和“订阅购买/重置”向用户发放带来源的幸运卡。用户消耗一张幸运卡完成一次抽奖，奖品根据幸运卡来源产生不同的额度、有效期和套餐行为。

产品目标：

1. 鼓励真实余额充值和订阅套餐购买。
2. 让日限额、周限额等周期套餐持续产生可感知权益。
3. 保持幸运卡、抽奖结果、奖励套餐和原始来源之间可追溯。
4. 避免赠金、活动奖励或免费套餐递归产生新的幸运卡。
5. 让多套餐用户自行决定未绑定 API Key 的订阅消耗顺序。
6. 保证抽奖、发卡和奖品发放幂等、可审计、可申诉。

非目标：

- 幸运卡不能提现、转让、赠送或兑换现金。
- 活动奖励不参与代理分红、邀请返佣、累计充值、购卡赠卡或再次抽奖资格计算。
- 转盘动画不参与随机结果计算。
- 首期不提供幸运卡交易市场、好友赠卡或用户自定义概率。

## 3. 核心术语

### 3.1 幸运卡

一次抽奖凭证。每张幸运卡有独立编号、来源、规则版本、发放时间、到期时间和状态。

### 3.2 充值来源幸运卡

用户通过活动期间符合条件的钱包真实充值，累计跨越指定人民币门槛后获得的幸运卡。

### 3.3 订阅来源幸运卡

用户通过符合条件的周卡/月卡购买，或符合条件的订阅实例完成周期额度重置后获得的幸运卡。该卡必须绑定具体订阅实例。

### 3.4 来源订阅实例

产生订阅来源幸运卡的具体 `user_subscriptions` 实例，不是套餐模板或分组。奖品的分组、剩余有效期和特殊卡行为以该实例的冻结快照为依据。

### 3.5 奖励订阅实例

由套餐额度、套餐双倍卡、套餐全额重置卡或 5 小时狂蹬卡产生的订阅实例。所有奖励实例均为活动出资，永久禁止再次产生幸运卡。

### 3.6 钱包本金与钱包赠金

- 钱包本金：可用于 API 消费和购买允许余额支付的订阅套餐。
- 钱包赠金：永久有效，可用于 API 消费，但不可购买任何订阅套餐。

## 4. 用户资格与通用规则

1. 只有状态正常的用户可以获得和使用幸运卡。
2. 幸运卡与用户账号绑定，不可转让、赠送、出售或提现。
3. 每张幸运卡只能成功抽奖一次。
4. 每次抽奖必须由用户明确选择一张具体幸运卡。
5. 不同来源的幸运卡使用不同奖池和奖励语义，系统不得只保存“可抽次数”而丢失来源。
6. 用户抽奖时展示所选幸运卡的来源、来源实例、到期时间、可中奖范围和概率。
7. 免费或活动派生权益永久禁止再次产生幸运卡。
8. 管理员直接绑定套餐、赠送套餐或补发活动奖励不视为真实订阅购买，默认不产生幸运卡；管理员补发幸运卡必须走独立补偿入口并写明原因。

## 5. 幸运卡获取规则

### 5.1 累计充值阶梯

仅统计符合条件的钱包真实充值到账金额，单位为人民币分。

| 第几张充值卡 | 累计充值门槛 |
|---:|---:|
| 1 | 50 元 |
| 2 | 100 元 |
| 3 | 200 元 |
| 4 | 400 元 |
| 5 | 600 元 |
| 6 | 800 元 |
| 7 | 1000 元 |
| 8 | 1200 元 |
| 后续 | 每张在上一门槛基础上增加 200 元 |

计算公式：

- 第 1 至第 6 张使用固定门槛 `50/100/200/400/600/800` 元。
- 第 `n` 张（`n >= 7`）门槛为 `800 + (n - 6) × 200` 元。

发卡规则：

1. 一笔充值跨越多个门槛时，一次性发放跨过的全部幸运卡。
2. 拆分充值和一次性充值的最终卡数一致。
3. 每个支付订单只能记入一次，支付回调重试不得重复发卡。
4. 充值门槛进度永久累计，不按自然月或活动版本重置。
5. 退款或拒付会冲销合格金额，但已经跨越并记录的历史门槛不回退，也不会在以后重复跨越同一门槛再次发卡。
6. 退款关联的未使用幸运卡失效；已使用幸运卡及奖励进入退款审核，不自动删除用户已经消费的权益。

计入充值阶梯：

- 在线钱包充值实际到账金额。

不计入充值阶梯：

- 订阅套餐的外部支付订单；
- 后台加额；
- 钱包赠金；
- 兑换码；
- 邀请返佣、代理分红；
- 活动奖励；
- 签到、补偿、直接覆盖余额；
- 退款、拒付或撤销交易。

### 5.2 购买周卡/月卡立即发卡

管理员在套餐上架或编辑时配置：

- `立即获得幸运卡：n 张`
- `每次额度重置赠送 1 张幸运卡：是/否`

产品规则：

1. `n` 为非负整数，`0` 表示不赠送。
2. 套餐卡片仅在 `n > 0` 时展示“立即获得幸运卡：n 张”。
3. 开启周期赠卡时同时展示“每次额度重置赠送：1 张幸运卡”。
4. 用户通过外部支付或钱包本金购买符合条件的套餐，支付成功并创建订阅实例后立即获得 `n` 张幸运卡。
5. 后台加额进入钱包本金后，使用该本金购买周卡/月卡可以正常获得幸运卡。
6. 钱包赠金不能购买订阅，因此不存在赠金购卡后再次产生幸运卡的路径。
7. 订单价格为 0、管理员直接绑定套餐、活动奖励套餐、套餐双倍卡、套餐全额重置赠送周期和 5 小时狂蹬卡均不产生购卡幸运卡。
8. 每个真实购买订单只发放一次；支付回调、页面重试和任务补偿必须返回同一结果。
9. 下单时冻结套餐的幸运卡权益快照。支付订单在有效期内完成时按快照发卡，不受下单后套餐编辑影响。

### 5.3 周期重置发卡

1. 只有套餐快照明确开启“每次额度重置赠送 1 张幸运卡”的正常购买实例才参与。
2. 每完成一个真实额度重置周期，发放 1 张幸运卡。
3. 日重置、周重置、月重置和自定义周期统一以实例的实际重置时间为准。
4. 系统停机跨过多个应重置周期时，恢复后补齐每个符合条件且未处于“暂停发卡”的周期。
5. 每个“订阅实例 + 重置周期”最多产生一张卡。
6. 套餐额度奖励实例不继承周期重置。
7. 套餐双倍奖励实例即使继承原套餐重置行为，也永久禁止产生幸运卡。
8. 套餐全额重置开启的新赠送周期不产生幸运卡。

## 6. 幸运卡有效期

### 6.1 充值来源幸运卡

- 从发放成功时起 30 天有效。

### 6.2 订阅来源幸运卡

- 到期时间冻结为发卡时来源订阅实例的结束时间。
- 来源套餐后续续费、双倍、全额重置或套餐模板编辑，不自动延长既有幸运卡。

### 6.3 暂停抽奖的冻结

1. 暂停抽奖期间，所有仍可用幸运卡不可使用。
2. 暂停开始时尚未到期的幸运卡冻结剩余有效期。
3. 恢复抽奖后，卡片到期时间按暂停时长顺延。
4. 对订阅来源幸运卡，奖励计算使用的“有效来源结束时间”同步顺延，但不会延长原订阅实例本身。
5. 来源实例退款、作废或因风控被撤销时，卡片仍可被撤销，不因暂停冻结获得额外权利。

## 8. 奖品发放语义

### 8.1 套餐额度

订阅来源：

1. 奖励继承来源实例的限定分组。
2. 奖励到期时间等于该幸运卡的有效来源结束时间。
3. 奖励额度为一次性生命周期额度，不继承日/周/月重置。
4. 同一来源实例、同一有效结束时间第一次抽中套餐额度时创建奖励实例。
5. 后续同来源、同结束时间再次抽中套餐额度时，累加到已有奖励实例，不再创建新实例。
6. 奖励实例不改变原实例额度，不产生幸运卡。

充值来源：

1. 每次抽中套餐额度，在转盘面额基础上额外增加 60 美元。
2. 每次中奖创建独立奖励实例，从中奖成功时起 30 天有效。
3. 首期默认限定“套餐专用分组”；后台必须允许配置活动套餐分组，规则页展示当前分组名称。
4. 奖励额度为一次性生命周期额度，无周期重置。

### 8.2 钱包赠金

1. 发放到用户钱包赠金池。
2. 永久有效。
3. 可用于任意用户有权访问的分组进行 API 消费。
4. 不可提现、转账或购买订阅套餐。
5. 不计入充值阶梯、购卡资格、返佣、分红或活动成本收入。

### 8.3 套餐双倍卡

1. 仅订阅来源幸运卡可以抽中。
2. 以来源订阅实例的购买权益快照为准，创建一份完整额度的独立奖励实例。
3. 新实例的结束时间等于幸运卡的有效来源结束时间。
4. 新实例继承来源套餐的限定分组和周期重置规则。
5. 新实例不复制来源实例的 API Key 绑定，由用户自行绑定或参与未绑定 Key 的消耗排序。
6. 新实例永久禁止产生幸运卡。
7. 新实例实付收入为 0，不参与分红、返佣或退款。

### 8.4 套餐全额重置卡

1. 仅订阅来源幸运卡可以抽中。
2. 关闭来源实例的原权益周期，并在同一订阅谱系中开启新的活动赠送周期。
3. 新周期从中奖成功时间开始，恢复来源套餐快照中的完整有效时长、周期额度和总额度上限。
4. 原消费、成本、订单、Key 绑定、续费关系和审计记录不得删除或覆盖。
5. 已绑定来源实例的 API Key 原子切换到新周期。
6. 已提前购买的续费后继实例顺延到新赠送周期结束后，用户已购买时长不得被覆盖。
7. 新赠送周期不产生幸运卡，实付收入为 0，不参与分红、返佣或退款。

### 8.5 5 小时狂蹬卡

1. 从中奖成功时间起有效 5 小时。
2. 固定总额度为 600 美元对应的平台额度。
3. 默认限定“套餐专用分组”，后台可配置活动专用分组。
4. 无周期重置、不可续费、不可退款、不可转赠。
5. 不产生幸运卡，不参与分红或返佣。

## 9. 套餐消耗顺序

### 9.1 生效范围

1. 用户在“我的订阅”中按限定分组设置当前有效订阅实例的消耗顺序。
2. API Key 明确绑定具体订阅实例时，不受用户全局排序影响。
3. API Key 未绑定具体实例时，按当前请求分组对应的用户顺序寻找可用实例。
4. 不同分组分别排序；通用订阅可以出现在多个分组的排序中。

### 9.2 扣费规则

1. 一次请求只使用一个订阅实例，不跨实例拆分扣费。
2. 请求开始时冻结实际扣费实例，执行中调整顺序不影响在途请求。
3. 排在前面的实例额度不足以完成预扣、已过期、已暂停或分组不兼容时，跳过并尝试下一实例。
4. 新增但尚未排序的实例排在手动排序实例之后，再按最早到期、实例编号较小优先。
5. 活动奖励实例与普通实例一起展示，并标明来源、到期时间和“不产生幸运卡”。
6. 已绑定 Key 继续按自身配置的续费后继、同分组接续和钱包兜底策略运行。

## 10. 用户端页面

### 10.1 活动入口

- 登录后侧栏增加“幸运大转盘”。
- 钱包充值成功页、订阅购买成功页和周期赠卡通知可跳转活动页。
- 活动暂停时入口继续可见，并显示暂停原因和恢复后的卡片处理说明。

### 10.2 活动页信息架构

桌面端：

1. 左侧：转盘、当前卡片、抽奖按钮、来源提示和规则入口。
2. 右上：可用幸运卡总数、最近奖励、奖池奖项数。
3. 右中：距离下一张充值来源幸运卡的累计充值进度。
4. 右下：我的幸运卡列表，可按来源、状态和到期时间筛选。
5. 底部：抽奖记录。

移动端：

1. 当前幸运卡选择器；
2. 转盘与抽奖按钮；
3. 充值进度；
4. 幸运卡列表；
5. 抽奖记录；
6. 活动规则。

### 10.3 幸运卡选择器

每张卡展示：

- 卡号；
- 来源类型；
- 来源套餐名称、实例号和用户备注（订阅来源）；
- 获得原因：购买、周期重置、累计充值、管理员补偿；
- 发放时间；
- 到期时间；
- 奖池类型；
- 可中奖范围；
- 状态。

默认选择最早到期的可用卡，但用户可以切换。抽奖按钮必须再次展示“将使用哪张幸运卡”。

### 10.4 转盘展示

1. 转盘动画仅呈现服务端已确定结果。
2. 转盘扇区面积不作为概率说明；页面必须提供完整概率表。
3. 奖项较多时可以按“套餐额度、钱包赠金、特殊卡”进行视觉分组，但结果弹窗必须展示具体奖项。
4. 尊重系统“减少动态效果”设置；关闭动效时直接展示结果。
5. 抽奖请求进行中禁止重复点击。

### 10.5 抽奖结果

结果弹窗展示：

- 奖品名称；
- 转盘面额；
- 实际发放额度；
- 幸运卡来源；
- 奖励实例号或赠金流水号；
- 生效时间与到期时间；
- 限定分组；
- “查看我的订阅”或“查看钱包”入口。

### 10.6 抽奖记录

记录字段：

- 抽奖时间；
- 幸运卡编号；
- 幸运卡来源；
- 来源订阅实例；
- 规则版本；
- 奖项；
- 转盘面额；
- 实际发放；
- 奖励实例或钱包流水；
- 到期时间；
- 发放状态；
- 申诉编号。

## 11. 管理员功能

### 11.1 活动控制

提供两个相互独立的开关：

1. 暂停发卡：
   - 新创建的充值订单、订阅订单和新发生的重置周期不再获得活动资格；
   - 暂停前已向用户展示并冻结资格的有效待支付订单，支付成功后仍履行承诺；
   - 暂停期间发生的周期重置不补发。
2. 暂停抽奖：
   - 用户不能消耗幸运卡；
   - 已有可用卡冻结有效期；
   - 恢复前先完成到期时间顺延，再开放抽奖。

后台操作必须记录操作者、时间、原因、前后状态和影响卡数。

### 11.2 套餐配置

套餐新增：

- 立即赠送幸运卡数量；
- 每次周期重置是否赠送 1 张；
- 用户端展示预览；
- 最高可能奖值与合规提示。

配置写入订单权益快照，修改不追溯已有订单和实例。

### 11.3 规则版本

1. 已启用规则版本不可原地修改。
2. 调整概率、面额、额外额度、有效期或充值门槛时创建新版本。
3. 每张幸运卡绑定发放时的规则版本。
4. 旧卡继续使用旧版本；新版本只影响生效后新发放的卡。
5. 新版本发布前显示概率和名义期望预览，并执行总权重等于 1000000 的强校验。

### 11.4 运营看板

至少展示：

- 发卡数：按来源、套餐、日期；
- 可用、已使用、已过期、已撤销卡数；
- 抽奖次数与各奖项实际命中率；
- 理论概率与实际概率偏差；
- 套餐额度、赠金和特殊卡名义价值；
- 按渠道成本倍率估算的实际成本；
- 发奖失败、重试和待人工审核数；
- 退款/拒付关联卡数；
- 用户异常集中充值、抽奖和退款行为。

### 11.5 人工补偿

管理员可以补发指定奖池类型的幸运卡，但必须填写：

- 用户；
- 卡片来源类型；
- 订阅来源实例（订阅奖池必填）；
- 数量；
- 到期时间；
- 补偿原因；
- 关联工单。

补偿操作不能直接指定随机抽奖结果。确需直接补发奖品时，使用独立“人工奖励”流程并与随机抽奖记录区分。

## 12. 状态与异常处理

### 12.1 幸运卡状态

- `available`：可使用；
- `consumed`：已完成抽奖并成功发奖；
- `expired`：超过有效期；
- `revoked`：退款、拒付、风控或管理员依法撤销；
- `review_required`：已使用但来源交易发生退款/争议，等待人工处理。

### 12.2 抽奖异常

1. 网络重试：同一幂等键返回原结果。
2. 重复点击：第二次请求不得再次扣卡。
3. 发奖失败：整个数据库事务回滚，卡片保持可用；不可出现“卡已扣、奖未发”。
4. 客户端动画中断：刷新后从抽奖记录恢复结果。
5. 卡片刚好到期：以服务端事务读取的数据库时间判定。
6. 来源退款：未使用卡撤销；已使用记录进入审核。

## 13. 通知

站内通知：

- 获得幸运卡；
- 幸运卡 7 天、3 天、1 天内到期；
- 抽奖成功；
- 奖励实例创建；
- 活动暂停/恢复；
- 卡片因退款或拒付撤销；
- 奖品发放异常恢复。

邮件：

- 套餐双倍卡；
- 套餐全额重置卡；
- 5 小时狂蹬卡；
- 奖励发放失败超过告警阈值；
- 退款争议需要用户处理。

同一事件只发送一次，通知失败不回滚已经成功的抽奖事务。

## 14. 公开活动规则要求

公开规则页必须至少包含：

1. 活动名称、长期有效说明和暂停机制；
2. 主办方和联系方式；
3. 参与条件与获得幸运卡的方式；
4. 两套奖池、奖项和中奖概率；
5. 充值门槛；
6. 奖励额度、使用范围、限定分组和有效期；
7. 赠金不可购买套餐、不可提现；
8. 幸运卡不可转让；
9. 套餐双倍、全额重置和 5 小时狂蹬卡的完整解释；
10. 退款、拒付、异常订单和弃奖处理；
11. 抽奖结果查询和申诉方式；
12. 规则版本生效时间。

合规发布门禁：

- 上线前完成正式规则页和客服联系方式；
- 核对同一次购买可能获得的多张卡及累计最高奖值；
- 按同期市场价格核算非现金奖品价值；
- 保存规则版本、公示内容、发卡、抽奖、获奖和兑奖记录至少两年；
- 正式上线前由熟悉互联网促销的法律顾问复核。

## 15. 验收标准

### 15.1 发卡

- 同一充值回调执行 10 次只产生一次进度和对应门槛卡。
- 一笔充值跨越多个门槛时卡数正确。
- 赠金、兑换码、返佣、后台加额不会增加充值阶梯。
- 后台加额形成的钱包本金购买套餐可以获得套餐配置卡。
- 钱包赠金无法购买订阅。
- 免费/活动奖励实例永不产生幸运卡。
- 每个重置周期最多发一张，停机恢复可以补齐符合条件的周期。

### 15.2 抽奖

- 两套奖池权重均严格等于 1000000。
- 充值来源卡无法命中双倍卡和全额重置卡。
- 同一卡并发 100 次抽奖只成功一次。
- 同一幂等键重试返回完全相同结果。
- 发奖失败时卡片不丢失。
- 客户端无法控制或覆盖随机结果。

### 15.3 奖励

- 充值来源套餐额度正确增加 60 美元。
- 订阅来源套餐额度不额外增加 60 美元。
- 套餐额度奖励无周期重置。
- 同来源同到期时间的套餐额度奖累加到同一奖励实例。
- 双倍卡复制完整权益但不复制 Key、不产卡。
- 全额重置保留历史并正确迁移 Key/续费链。
- 钱包赠金永久有效且不能购买订阅。
- 5 小时狂蹬卡按服务端时间准确到期。

### 15.4 排序

- 未绑定 Key 按用户当前分组顺序扣费。
- 已绑定 Key 完全不受全局顺序影响。
- 在途请求不因排序修改更换实例。
- 新增未排序实例使用确定性的兜底顺序。

### 15.5 暂停

- 暂停发卡不影响已有卡。
- 暂停抽奖期间不能抽奖。
- 恢复抽奖前所有可用卡按暂停时长顺延。
- 多次暂停累计顺延准确且幂等。
